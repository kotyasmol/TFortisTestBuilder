# Диагностика 8x2Pro на стенде

## Изолированная проверка native-очередей

`NativeQueueProbe.ps1` — Windows/PowerShell 5.1, установленный Npcap/WinPcap
x64, две уже настроенные физические карты в подсети 192.168.0.x. Нужны
активные линки не ниже выбранной цели и разрешение на передачу через DUT.
Программа стенда может оставаться открытой, но аппаратный тест не должен идти.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/BenchProbe/NativeQueueProbe.ps1 -SourceIp 192.168.0.3 -DestinationIp 192.168.0.2 -DurationMs 500 -Senders 1 -ExecuteTraffic
```

`-Senders 2` проверяет два независимых injection handle. Кадры имеют разные
sequence по отправителям; считаются только уникальные кадры текущего запуска.
Без явного `-ExecuteTraffic` отправки нет. Длительность каждого измерения
ограничена 100–1000 мс. По умолчанию цель — 1000 Мбит/с;
`-TargetMbps 100 -IndividualOnly -DurationMs 5000` проверяет точную
покадровую отправку на 100 Мбит/с без native-очередей. В этом режиме
допускается до 5000 мс и один либо два отправителя; опоздавшие интервалы
не отыгрываются пачкой.
Шесть вариантов очередей: для 2 и 20 мс отдельно
проверяются отправка с pacing/без него и синхронизация кадров. Можно задать
`-QueueWindowsMs 100 -SynchronizedOnly` для отдельного сравнения. Параметр
`-TimestampRateScale` (1–1,1, по умолчанию 1) изменяет только интервалы кадров
в эксперименте; в производственный DataTest он не переносится.
Очереди предварительно готовятся до
измерения; раздельно фиксируются подготовка, native-вызовы и boundary wait.
Максимальная подготовленная память — около 128 МБ при 1000 мс, очереди и
handles освобождаются после каждого варианта, потоки дожидаются завершения.
Неполная отправка, RX или потери захвата дают код завершения 1.

Используются существующие wpcap/Packet.dll. Скрипт не меняет IP, свойства
карт или профиль, не открывает COM, не управляет питанием, не печатает и не
отправляет отчёт. Результат — `native-queue-probe-result-1.json` или `-2.json`
рядом со скриптом. Это диагностические замеры, не производственная приёмка:
строка с Error, неполным RX либо capture drops не подтверждает исправный тракт.

## Изолированный запуск производственной ноды DataTest

После сборки BenchProbe на Windows:

```powershell
BenchProbe.exe --execute-datatest 192.168.0.2 192.168.0.3 1000
```

Последний аргумент — 100 или 1000 Мбит/с. Это настоящий `RunDataTestStep`:
пакет 1514 байт, прогрев 500 мс, измерение 5000 мс в каждую сторону,
допуск потерь 1%, дефицита скорости 2%. Команда требует уже настроенных IP
и включённого оборудования. Основной тест приложения должен быть остановлен.
COM, граф профиля, выдача номера, печать и отправка отчёта не запускаются.
Профили не читаются и не сохраняются. Код завершения 0 и
`ISOLATED_DATATEST_RESULT=True` означают успех выбранной пары;
вывод содержит реальные TX/RX, скорость, потери и ошибки NIC.
Ctrl+C отменяет запуск, общее время ограничено тремя минутами.

## Полный аппаратный диагностический цикл

Только Windows и штатный `PSW+UPS-Box 8x2Pro · Параллельная проверка с SFP · 11.11.26.json`.
Запуск действительно управляет подключённым оборудованием; требуется
разрешение оператора. Перед запуском освободить COM-порт, остановив приложение.

```powershell
dotnet build tools/BenchProbe/BenchProbe.csproj -c Release
dotnet tools/BenchProbe/bin/Release/net8.0/BenchProbe.dll profiles/PSW+UPS-Box 8x2Pro · Параллельная проверка с SFP · 11.11.26.json COM3 --execute-8x2pro hardware 1
```

Режим `hardware` выполняет штатные подтесты подготовки, настройки PoE,
питания, selftest, нагревателей, медного DataTest и UPS, затем десять
повторных selftest. Режим `selftest` оставляет подготовку, питание,
ожидание загрузки и двенадцать чтений selftest. Последний аргумент — число
циклов (1–10); в конце каждого цикла питание выключается и проверяется.

Используются реальные GraphCompiler, TestExecutor, ModbusService и
RegisterMonitor. Параметры и допуски берутся из JSON. SFP выключен только
в памяти этого процесса. JSON и его расположение не сохраняются.
Серийник, запись MAC, этикетки и отправка производственного отчёта не запускаются.
Это диагностика выбранных аппаратных этапов, не полный производственный выпуск.

Chrome/Edge выбирается как в приложении: сначала `Browser/chrome-win64/chrome.exe`
рядом с диагностическим exe, затем установленный Chrome/Edge. Для воспроизводимости
использовать тот же комплект Browser, что и на исследуемой машине.

Ctrl+C отменяет текущую проверку, затем выполняется аварийное выключение
профиля, сброс PoE-нагрузок и чтение AC1/AC2, нагревателей и ключа SIMBAT.
При ошибке любой проверки или выключения следующий цикл не начинается.
`CLEANUP_CONFIRMED` подтверждает прочитанные выключенные выходы;
`BENCH_PROBE_SUCCESS` — успех всех выбранных проверок.
