# Исходные параметры RTL

RTL_SW_v1.json и RTL_POE_v1.json предоставлены владельцем 2026-10-19.
Файлы скопированы без изменения содержимого. Это формат старого приложения,
не графы TestBuilder: открывать в редакторе нужно profiles/RTL_SW_board.json
и profiles/RTL_POE_board.json.

tools/rtl_source_profiles.py переносит значения в сгенерированные графы;
generate_rtl_profiles.py вызывает его перед сохранением. Скрипт не запускается
при открытии приложения и не перезаписывает пользовательские копии профилей.
После его отдельного запуска требуется ProfileLayout --write, затем --check.

Перенесены все аппаратные пределы и задержки, версии MCU/прошивок, флаги
подтестов, цвет LED, выбор портов, пауза загрузки PoE и число этикеток.
Отключённые в оригиналах отчёты и печать остаются отключёнными. Широкие
допуски PoE сохранены буквально, без самостоятельного ужесточения.

Исключения по согласованному поведению TestBuilder:

- Прошивка вручную; mcu_firmware_auto=true из PoE не включает прошивальщик.
- Windows-пути к утилитам и прошивкам не исполняются и не подставляются.
- Физический RUN не проверяется; запуск и отмена выполняются в приложении.
- Серверные операции используют клиент TestBuilder, без FTServiceUtils.
  model_type/model_name старого сервера не подменяют аппаратные ID стендов
  104/105 или существующие типы запросов RTL-SW/RTL-POE.
- Отключённая печать использует прежний EPL 30×10; label_size=20 не принят
  за подтверждённый физический формат принтера.
- k5_start_delay, dut_start_time, dut_end_of_new_logs_time и границы
  температуры I2C сохранены в исходном файле, но соответствующие сервисы
  RTL_v2 86f7dbd не используют их как параметры текущего алгоритма.
  Новые ограничения температуры не добавлены.

2329 (k5_test_delay) и 2332 (vcc_start_delay) получают **10**, как в исходнике,
без перевода в миллисекунды. Ранее в обоих регистрах ошибочно задавалось 2000.
Это вероятная причина длительного состояния К5=1; аппаратное подтверждение
исправления ещё требуется. Полный список отличий: docs/RTL_boards_migration.md.
