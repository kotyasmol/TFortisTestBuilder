# Рабочая память проекта TFortisTestBuilder

Этот файл — короткая точка входа для работы с репозиторием. Прежде чем
изучать исходники заново, прочитайте релевантные заметки из
[`docs/obsidian`](docs/obsidian). Они описывают фактическое состояние
проекта на `master` (сверка текущего кода — 2026-10-28).

## Как использовать базу знаний

1. Всегда начните с [`00 - Главная`](docs/obsidian/00%20-%20Главная.md).
2. Выберите только тематические заметки из таблицы ниже.
3. Открывайте код точечно, когда задача требует изменения, проверки
   актуальности или точного поведения метода. Markdown — карта и рабочий
   контекст; исходный код остаётся источником истины.
4. После изменения архитектуры, формата JSON, ноды, интеграции или состава
   моделей обновите соответствующую заметку и
   [`13 - Карта актуальности`](docs/obsidian/13%20-%20Карта%20актуальности.md).

## Неподвижные ориентиры

- Основное приложение: `TestBuilder` — Avalonia/.NET 8.
- Тесты: `TestBuilder.Tests` — xUnit.
- Центральная цепочка выполнения: visual `NodeViewModel` → `GraphCompiler`
  → `CompiledGraph`/`TestNode` → `TestExecutor` → `ITestStep` → `StepResult`.
- Общие сервисы вручную создаёт `MainWindowViewModel`; DI-контейнера нет.
- GitHub-репозиторий: `kotyasmol/TFortisTestBuilder`; локальная ветка —
  `master`.
- В `.codex/QTstand_old` находится исторический Qt-проект. Это не часть
  .NET-решения и его нельзя менять без отдельного запроса.

## Границы документации

Заметки используют Obsidian wiki-links и должны оставаться в UTF-8. Не
перезаписывайте незакоммиченные изменения пользователя в `docs/obsidian`.
При расхождении заметки с кодом исправьте заметку и отметьте это в карте
актуальности.

## Сборка и серверная публикация

Для выпуска и публикации используйте `docs/obsidian/28 - Сборка и публикация обновления.md`
и skill `tfortis-release` (исходник: `skills/tfortis-release/SKILL.md`). Запрос
только на сборку заканчивается проверенным ZIP; сервер обновляется, когда это
входит в запрос. Версию, фактическую ветку, device ID и маркер каждый раз
проверяйте заново. Публикация включает проверенную резервную копию и изменение
маркера только после проверки всех файлов.

## Единственная рабочая копия на АПК‑03

Отладка Visual Studio, запуск приложения и `dotnet test` на АПК‑03 выполняются
только из `C:\Users\АПК-03-07\Documents\GitHub\TFortisTestBuilder`.
Не создавать на этом компьютере дополнительные клоны, worktree, диагностические
проекты и копии приложения в `Temp`, на рабочем столе или рядом с основным
репозиторием. Это прямое требование пользователя от 2026-11-11.
Перед обновлением рабочей копии проверять локальные правки и сохранять
пользовательские профили; не заменять эту проверку созданием другой копии.

## Тексты интерфейса и справки

Пользователь просит короткие предметные подписи без рекламных фраз, риторических
пар и искусственных конструкций вроде «Одна картинка — шесть элементов». Не
добавлять очевидные пояснения и декоративные слоганы. Инструкция предназначена
для сотрудников производства: конкретные кнопки, последовательность действий,
ожидаемый результат, ограничения и отдельная справка для каждой ноды.

## Отображение и данные профиля

`RussianUiTextConverter` — строго односторонний переводчик. Не добавляйте в
него ConvertBack или параметры для записи подписей в исходные поля. Для
редактируемого служебного значения используйте исходный ключ в SelectedItem
и отдельный шаблон подписи либо специализированное обратимое преобразование
только этого поля. Названия в таблицах отображаются через TranslatedNameColumn,
а редактируются как исходная строка.

При изменении UI нод/конвертеров выполните ProfileUiIntegrityTests,
RussianInterfaceTests и DataTestModeTests. Простое открытие редактора не должно
менять параметры ноды, вложенных графов или кнопок. Упаковщик релиза запускает
эти проверки автоматически до публикации.

## Генерация профилей

При автоматическом создании или изменении профиля проверяйте размещение по
фактическим размерам его нод в редакторе, включая все тела подтестов и циклов.
Одинаковый шаг сетки для разных типов нод не обеспечивает отсутствие наложений.
Используйте `tools/ProfileLayout` для размещения и повторной проверки загруженного
файла; порядок действий описан в `docs/profile-layout.md`. Ручное расположение
пользовательских профилей автоматически не заменяйте.
