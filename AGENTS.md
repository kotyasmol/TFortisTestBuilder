# Рабочая память проекта TFortisTestBuilder

Этот файл — короткая точка входа для работы с репозиторием. Прежде чем
изучать исходники заново, прочитайте релевантные заметки из
[`docs/obsidian`](docs/obsidian). Они описывают фактическое состояние
проекта на `master` (проверено 2026-07-14).

## Как использовать базу знаний

1. Всегда начните с [`00 - Главная`](docs/obsidian/00%20-%20Главная.md).
2. Выберите только тематические заметки из таблицы ниже.
3. Открывайте код точечно, когда задача требует изменения, проверки
   актуальности или точного поведения метода. Markdown — карта и рабочий
   контекст; исходный код остаётся источником истины.
4. После изменения архитектуры, формата JSON, ноды, интеграции или состава
   моделей обновите соответствующую заметку и
   [`13 - Карта актуальности`](docs/obsidian/13%20-%20Карта%20актуальности.md).

## Неподвижные ориентиры

- Основное приложение: `TestBuilder` — Avalonia/.NET 8.
- Тесты: `TestBuilder.Tests` — xUnit.
- Центральная цепочка выполнения: visual `NodeViewModel` → `GraphCompiler`
  → `CompiledGraph`/`TestNode` → `TestExecutor` → `ITestStep` → `StepResult`.
- Общие сервисы вручную создаёт `MainWindowViewModel`; DI-контейнера нет.
- GitHub-репозиторий: `kotyasmol/TFortisTestBuilder`; локальная ветка —
  `master`.
- В `.codex/QTstand_old` находится исторический Qt-проект. Это не часть
  .NET-решения и его нельзя менять без отдельного запроса.

## Границы документации

Заметки используют Obsidian wiki-links и должны оставаться в UTF-8. Не
перезаписывайте незакоммиченные изменения пользователя в `docs/obsidian`.
При расхождении заметки с кодом исправьте заметку и отметьте это в карте
актуальности.
