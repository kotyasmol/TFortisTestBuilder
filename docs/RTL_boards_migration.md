# Перенос RTL-SW и RTL-POE в TestBuilder

Обновлено: 2026-10-19. Исходник RTL_v2: `86f7dbd7cadf4c72f7a3e0763ce0fc4d72123687`.
База TestBuilder: `2395250329c54e80f1e56fb151f50e26b461a312`.

Реализация находится в рабочем дереве. Проверки оборудования представлены обычными
редактируемыми JSON-графами TestBuilder. 2026-10-19 владелец предоставил
RTL_SW_v1.json и RTL_POE_v1.json. Их параметры заменили временные значения
в двух профилях. Оригиналы сохранены в tools/RtlProfileMigration/SourceProfiles,
перенос параметров выполняет tools/rtl_source_profiles.py.
Это перенос исходного поведения с явно перечисленными адаптациями, а не утверждённая
методика приёмки и не свидетельство физического прогона стенда.

## Принятые решения

- Нет новой БД: граф, оборудование и картинка хранятся в JSON, текущие измерения —
  в `RegisterState`. Обновление для отдельного завода — отдельная копия профиля.
- Старое автоматическое определение АПК-03 сохранено для профилей без `hardware`.
  Пользовательская конфигурация задаётся в окне «Оборудование» без изменения C#.
- Один исполнитель и редактор. Фильтр «Коммутаторы / Платы», отдельный редактор платы
  и окно результатов добавляют ремонтный сценарий без второго приложения.
- For расширен режимом повторения тела без изменения slave, счётчиком, задержкой
  и завершением при первом успехе. Отдельных «Повтор» и «Для каждого» не добавлено.
- Новые ноды: Serial Console, Run Program, Parse Response, Check LED Color.
  Действие оператора дополнено вводом текста; сравнение — VersionAtLeast.
- Нет XGPro, эмуляции клавиш и FTServiceUtils. Прошивка выполняется вручную вне TB.
- Отчёт — действующий Build/Send Test Report. Этикетка платы — существующий EPL
  30×10 мм, полный серийный номер и Code128, явно одна копия.
- По решению владельца физический RUN исключён. Запуск и остановка
  выполняются кнопками TestBuilder, RUN не является условием прохождения графа.

консоли задаются локально в настройках. Сервер и Stand ID тоже локальные.
При импорте существующее имя файла не заменяется: используйте новое имя варианта
или заменяйте файл вручную после резервной копии и отключения стенда.

Пределы для самого контроллера задаются этапом подготовки.

Цвет и оба порога редактируются. Это проверка датчиков цвета стенда, не анализ фото.

## Формат и совместимость

`GraphDto` расширен корневыми `productKind`, `hardware`, `board`.
`hardware`: RTU-параметры, период опроса, список устройств; у устройства имя,
slave 1..247, необязательное значение/адрес идентификации, таблица регистров.
У регистра адрес 0..65535, область Holding/Input/Coil/Discrete, имя, единица,
категория и доступность записи. Это стандартные 16-битные/битовые значения;
Modbus TCP, произвольные function codes, float32/word-order автоматически не поддержаны.

`board`: встроенное растровое изображение и области Id/Name/X/Y/Width/Height
с нормализованными координатами. `boardElements` в ноде — список ID через запятую.
Редактор позволяет импорт фото, рисование/изменение/удаление прямоугольников;
просмотр — масштаб, перемещение и таблицу результатов. Исходные сложные контуры PoE
представлены охватывающими прямоугольниками. Это осознанное приближение геометрии.

Старые профили без новых полей загружаются по прежним правилам. Новые аппаратные
метаданные и области, режимы и ноды сериализуются так, чтобы старый runtime
отклонил неизвестный Start/For/Input, а не молча проигнорировал новое поведение.
Сначала обновляйте приложение на заводе, затем передавайте новый профиль.

После записи/консольного воздействия проверка требует опроса, начатого позже
команды; прямого дополнительного чтения графом нет. Неудачный опрос удаляет
значения соответствующего slave. Для конфигурируемого оборудования действует
предел возраста данных max(10 с, 3 периода опроса). Ноды ожидания ограничивают
ожидание свежести своим таймаутом. Смена профиля при подключении сначала останавливает мониторинг и разрывает связь.
Во время прогона смена профиля и ручная запись запрещены.

## Воспроизводимость

Из checkout RTL_v2 указанной ревизии:

```sh
dotnet run --project tools/RtlProfileMigration/RtlProfileMigration.csproj -- /path/to/RTL_v2/Resources/Images/PlateImages/rtl_poe_v3.svg /tmp/poe-board.json
python3 tools/generate_rtl_profiles.py /path/to/RTL_v2 /tmp/poe-board.json
dotnet build TestBuilder.Tests/TestBuilder.Tests.csproj
dotnet test TestBuilder.Tests/TestBuilder.Tests.csproj --no-build
```

Первый инструмент преобразует исходный SVG в PNG и области. Генератор создаёт
исходные редактируемые графы; не запускайте его поверх утверждённых заводских
вариантов без резервной копии. Параметры берутся из сохранённых оригиналов через rtl_source_profiles.py.
Адреса и ограниченные ожидания задаются в генераторе.

## Проверка и оставшиеся ограничения

Автотесты покрывают загрузку→сохранение→загрузку→компиляцию, исходные адреса и
порядок K5, отсутствие записей калибровки, 16 LED, строгие пороги цвета, повторы,
отмену, свежесть кэша, парсинг и ошибки, операции программ, отчёт и окна Avalonia.
Полный аппаратный граф SW/PoE выполняется на подставных ответах: задержки убраны,
отправка на сервер и печать выключены. Это проверка логики, не оборудования.

Нужен стендовой ввод в эксплуатацию: реальные COM, исправные и дефектные платы,
ревизия PoE, фактические версии SW/PoE, допуски, длительности, все линии питания,
потеря связи/остановка, серверные типы/серийники, печать и Windows-утилиты.
Ранний отказ SW без серийника сохраняет журнал, но не отправляет привязанный
серверный отчёт. Не следует подставлять фиктивный серийный номер.

Результаты сборок/регрессии и найденные ограничения безопасности фиксируются
отдельно в `docs/RTL_validation.md` и отчёте аудита Codex Security.

Отправка отчёта в новых профилях использует `failOnError=false`: технический статус доставки показывается отдельно и не превращает исправную плату в брак. Этикетка сама по себе не подтверждает доставку отчёта. При ожиданиях через повтор время включает ожидание свежего снимка Modbus; число попыток ограничено, но это не точный таймер реального времени.


## Проверка К5, 2026-10-19

Расхождение аппаратных задержек: k5_test_delay=10 и vcc_start_delay=10,
ранее в обоих регистрах задавалось 2000. SwStandPreparationService пишет
значения напрямую, без перевода единиц. Это вероятная причина длительного
состояния 1; исправление ещё требует прогона на физическом стенде.

Фоновый опрос — один блок с паузой 1000 мс после предыдущего чтения, как
в RTL_v2. Ожидания K5 читают кэш, не создают запросов на шину. Значение 1
считается ожиданием; ошибка выдаётся при исчерпании попыток или итоговом 3.

Исключения переноса параметров, включая неиспользуемые исходным кодом поля,
описаны в tools/RtlProfileMigration/SourceProfiles/README.md. Широкие допуски
PoE сохранены буквально. Оригинальные файлы не импортируются как графы.

Автотесты сверяют записи с исходными JSON, проверяют переходы K5 по времени,
зависание, отмену, старый кэш и отсутствие дополнительных Modbus-чтений.
Полные графы проверяются с исходными флагами; в сценариях отказов экспорта
отчёт и печать явно включаются только в памяти теста.
