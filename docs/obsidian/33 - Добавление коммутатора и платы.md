# Как добавить новый коммутатор или плату

Добавление изделия состоит из трёх частей. Справочник связывает модель с
серверным типом и этикеткой. Профиль определяет оборудование и порядок
проверок. Сервер хранит выделение серийных номеров и результаты. Для профиля
без серверной выдачи и отчётов достаточно локальной карточки и графа.

## 1. Подготовьте данные

| Что узнать | Где используется |
| --- | --- |
| Полное название изделия и ревизия | Название в справочнике, профиле и на этикетке. |
| Методика проверки и ограничения | Схема питания, прошивка, допустимые напряжения и сигналы, критерии отказа. |
| Подключения и карты регистров | Slave-адреса, параметры Modbus, область и адрес каждого регистра. Для DUT также укажите Ethernet или USB-UART, команды и форматы ответов. |
| Способ определить модель и прочитать идентификатор | У коммутатора это может быть поле модели или `dev_type` и `cpu_id`. У платы используйте тот идентификатор MCU, который ожидает сервер. |
| Данные регистрации на сервере | Точное имя типа для выдачи, правила присвоения номера и тестовый адрес. Для отчёта RTL нужны также числовой тип и отдельный служебный идентификатор для ранних отказов. |
| Данные этикетки | Код модели, коды комплектаций, формат EPL/ZPL, размер бумаги и очередь принтера. Для коммутатора с программированием MAC — база короткого номера, префикс MAC и, при записи Pro, имя платы для скрипта. |

Карточка в TestBuilder сохраняет настройки приложения. Регистрацию нового
серверного типа, диапазона и служебной записи выполняет администратор сервера.
Код на этикетке, серверный числовой тип RTL, код модели в прошивке и
Modbus slave — отдельные значения. Сверьте каждое с его источником.

## 2. Создайте рабочий профиль и карточку изделия

1. Перейдите в **Инженерный режим → Редактор**. На время редактирования остановите проверку.
2. Нажмите **Новый** для пустого графа. Если есть проверенный профиль с подходящей методикой, нажмите по нему ПКМ → **Копировать профиль**. Назовите копию, чтобы отличать её от рабочего профиля.
3. Над графом рядом с полем **Устройство** нажмите **+**. Если карточка уже есть, выберите её в списке и для правки откройте **Справочник → Редактировать изделие…**.
4. Заполните **Название изделия** при создании и нужные поля из раздела про коммутатор или плату. Нажмите **Сохранить в справочник**. Новая карточка автоматически выбирается в профиле.
5. В поле **Тип изделия** выберите **Коммутатор** или **Плата**. Введите **Название проверки**, например «Полная проверка · ревизия 2», и нажмите **Сохранить**.
6. В меню **Справочник** проверьте **Серийные номера из справочника**. Включите флажок для описанных ниже серверных схем. Для автономного профиля без настроенного серверного типа оставьте его выключенным.

Чтобы подготовить карточку отдельно от профиля, откройте **Справочник →
Все изделия…**. Здесь можно найти модель по названию или альтернативному
названию, добавить новую карточку и редактировать существующие. Чтобы
использовать добавленное изделие в профиле, выберите его в поле **Устройство**.

При копировании проверьте связи обеих ветвей, кнопки профиля, стартовые
подтесты, допуски, типы оборудования, адреса сервера и аварийное снятие
питания. У копии эти параметры сначала такие же, как у исходного графа.

## 3. Новый коммутатор

### Заполните серию

| Поле карточки | Что ввести | Пример для PSW+Box 8x2Pro |
| --- | --- | --- |
| **Тип на сервере** | Точное имя зарегистрированного типа для `getSerialNum`. | `PSW+Box 8x2Pro` |
| **Стартовый серийный номер** | Нижняя граница серии. | `3300001` |
| **Последний серийный номер** | Верхняя граница серии. | `3365535` |
| **База короткого номера** | Число, которое вычитается из полного номера. | `3300000` |
| **Код модели на этикетке** | Код из справочника этикеток, 0–999. В штрихкоде дополняется слева до трёх цифр. | `033` |
| **Префикс MAC** | Четыре утверждённых байта, если профиль рассчитывает или записывает MAC. | `C0:11:A6:21` |
| **Имя платы при записи Pro MAC** | Точное значение, которое принимает скрипт записи MAC, если этот шаг есть в графе. | `PSW+Box 8x2Pro` |

Стартовый номер ограничивает допустимый ответ. Конкретный номер выдаёт
сервер по типу и идентификатору коммутатора. Проверяйте полный диапазон над
графом. Если нужна комплектация, в карточке на вкладке **Изделие и этикетка**
заполните её название напротив кода, например **1** для K1 и **2** для DIN.
После сохранения выберите **Справочник → Комплектация этикетки**. Без
выбранного варианта используется цифра `0`.

### Настройте граф

1. В **Оборудование** проверьте контроллеры питания, нагрузки, реле и их адреса. Настройте сетевое подключение DUT, URL его страницы, паузы загрузки и параметры проверок под эту модель. Порядок настройки Modbus приведён ниже.
2. После подачи питания дождитесь загрузки DUT. Прочитайте его идентификатор, например в `Dut.cpu_id`, и доступное поле для распознавания модели. Добавьте проверку модели до выдачи номера. Если модель не распознана или не совпала, ветка выдачи номера не должна запускаться.
3. В ноде **Получение серийного номера** укажите переменную идентификатора и результат `SerialNumber`. Отключите фиксированный отладочный номер. При включённом справочнике тип и диапазон берутся из карточки модели. Подключите полный selftest и дальнейшие проверки после успешной выдачи. При отказе переведите граф к завершению с отключением питания.
4. Если методика требует записи MAC, добавьте **Расчёт MAC по серийному номеру** с входом `SerialNumber` и выходами, например `SerialShort` и `Dut.NewMac`. Выберите штатный способ записи для этой модели. После перезапуска прочитайте MAC с DUT и сравните его с ожидаемым. На этикетку передавайте подтверждённый MAC.
5. Настройте **Формирование отчёта → Отправка отчёта**. Источник номера — `SerialNumber`. У обеих нод должно совпадать имя переменной отчёта, например `TestReportText`. Стандартный путь для коммутатора — `/api/Api.svc/result.json`. Включите локальную копию. Чтобы задать состав, откройте **Состав отчёта…**, включите **Выбирать строки отчёта вручную**, отметьте нужные источники во вкладке **Переменные** и нажмите **Применить к профилю**.
6. Настройте **Печать этикетки** в формате ZPL. Выберите источник **Из переменных** и укажите полный номер и подтверждённый MAC. Для штатного шаблона проверьте в предпросмотре название, MAC, полный номер в строке SN и штрихкод. При базе `3300000` номер `3300579` даёт короткий номер `00579` и штрихкод `003300579` для комплектации `0`.
7. Проверьте аварийную ветку и штатное выключение питания. Для отчёта об отказе коммутатора нужен проверенный полный номер. Если номера ещё нет, сохраните причину в журнале прогона. Служебный маршрут RTL относится к платам с настроенным серверным контрактом.

## 4. Новая плата

### Изображение и подключения

1. После выбора типа **Плата** откройте **Плата**. Нажмите **Загрузить изображение** для нового PNG или **Шаблон платы…** для готового JSON с областями. Для шаблона его PNG должен быть доступен по пути, указанному в JSON. Поставляемые примеры лежат в `reference/boards/RTL`.
2. Обведите проверяемые элементы мышью или нажмите **Добавить область**. Задайте каждому элементу постоянный код, например `K5`, `VCC` или `LED1A`, и понятное название. Нажмите **Применить к профилю**.
3. В **Оборудование** добавьте контроллер стенда и остальные Modbus-устройства. Плата, с которой общаются по USB-UART, настраивается отдельно на вкладке **Консоли → Добавить консоль**. Задайте имя, скорость и способ выбора адаптера. Фиксированный COM-порт указывайте только там, где он нужен. В ноде **Консоль платы** выберите эту консоль. Если адаптер появляется после подачи питания, включите **Дождаться подключения** и задайте время ожидания.
4. Соберите последовательность проверок по методике платы. Укажите регистры, пороги, команды UART, ожидаемую ревизию или прошивку. В шестерёнке соответствующей ноды заполните **Элементы платы через запятую** кодами с изображения. Сверьте подсветку в пульте.

Если разметка нужна в нескольких профилях, возьмите JSON из
`reference/boards/RTL` за образец. Положите свой PNG рядом с новым JSON.
В `ImageFile` укажите имя PNG, а в `Regions` сохраните код `Id`,
название `Name` и координаты `X`, `Y`, `Width`, `Height` в долях
ширины и высоты изображения от 0 до 1. Проверьте импорт через
**Шаблон платы…**.

### Серийный номер и серверный отчёт

1. В карточке платы заполните название, **Тип на сервере** и код модели на этикетке. Если диапазон ведёт сервер, оставьте поля стартового, последнего номера и базы пустыми. Для уже поставляемых RTL-SW и RTL-POE параметры есть в справочнике.
2. Для **новой модели с контрактом RTL** откройте вкладку **Отчёт RTL** и включите **Использовать отчёт RTL**. Заполните поля по данным сервера.

   | Поле карточки | Значение |
   | --- | --- |
   | **Числовой тип отчёта на сервере** | Тип отчёта, подтверждённый сервером. У существующих RTL-SW и RTL-POE это 5 и 6 соответственно. |
   | **Переменная идентификатора платы** | Переменная с реальным идентификатором платы, обычно `CpuId`. |
   | **Получать серийный номер из ответа на отчёт** | Включите, если номер приходит в ответе. Оставьте выключенным, если номер запрашивается отдельной нодой. |
   | **Служебный идентификатор отказов** | Идентификатор для отказов этой модели до выдачи номера. Значение даёт администратор сервера. |

3. Нажмите **Сохранить в справочник** и выберите нужную модель в профиле. Включите **Серийные номера из справочника**. В графе прочитайте и проверьте идентификатор платы, сохраните его в настроенную переменную.
4. Соедините ноды по серверной схеме модели.

   | Схема | Порядок нод |
   | --- | --- |
   | Номер выдаётся до отчёта, как у RTL-SW | Чтение идентификатора → **Получение серийного номера** в `SerialNumber` → **Формирование отчёта** → **Отправка отчёта** → **Печать этикетки**. |
   | Номер возвращается с отчётом, как у RTL-POE | Чтение идентификатора → **Формирование отчёта** → **Отправка отчёта**. После подтверждённого ответа появляется `SerialNumber`, который использует **Печать этикетки**. |

   Используйте путь `/api/Api.svc/SendTestResultUniverse`. Для отправки
   нужна сессия лаунчера. Если берёте поставляемый профиль RTL за основу,
   явно проверьте включённость штатных подтестов **Отчёт TestBuilder** и
   **Этикетка платы**. В комплектных профилях они выключены.
5. Для штатной этикетки RTL используйте EPL с полным `SerialNumber`. Подключите печать к ветке подтверждённой доставки отчёта, если методика требует отчёт перед печатью. У ноды отправки включите **Ошибка ведёт по «Нет»**, чтобы сбой не попал на эту ветку.
6. В **Ещё → Аварийные действия** поставьте снятие питания первым, а отчёт об отказе после него. У отчёта сохраните проверки `Execution.SendFailureReport` и `ReportDelivery.Status` из штатного профиля RTL. При наличии подтверждённого номера отчёт привязывается к нему. При раннем отказе используется служебный идентификатор. Номер служебной записи используется для журнала и копии отчёта, а этикетка изделия требует его собственного номера.

После таймаута отправки проверьте историю на сервере перед повторным
прогоном. Потеря ответа и отсутствие записи на сервере могут выглядеть
одинаково в приложении.

## 5. Если у стенда новое Modbus-устройство

1. Откройте **Оборудование → Каталог оборудования**. Для готовой карты нажмите **Добавить выбранное в профиль**. Для своей карты нажмите **Новое оборудование…** или **Создать копию…**.
2. Укажите название, регистр типа и допустимые значения, если устройство их поддерживает. В таблице добавьте адреса, названия, область регистра, единицы и разрешение записи. В ноде **Запись регистра** выбираются области Holding или Coil. Сверьте область и адрес по карте устройства до записи.
3. Нажмите **Сохранить в каталог**, выберите новую запись и нажмите **Добавить выбранное в профиль**. На вкладке **Оборудование профиля** замените предложенный slave на фактический уникальный адрес. В **Подключение** проверьте скорость, чётность, число битов и опрос. Порт рабочего места выбирается в **Настройки → Подключения рабочего места → COM стенда** либо определяется автоматически.
4. Нажмите **Применить к профилю**, затем **Сохранить** в редакторе. Откройте ноды чтения и записи, проверьте выбранные устройство, область, адрес и значение. В профиле сохраняется копия карты.

Для переноса только состава и настроек подключений используйте
**Оборудование → Подключение → Экспорт оборудования…** и
**Импорт оборудования…** на другом стенде. Свои записи в каталоге
оборудования сохраняются локально.

## 6. Проверка перед передачей в производство

1. В **Настройки → Сервер и стенд** проверьте **Адрес сервера** и **Идентификатор стенда**. Для единого адреса оставьте адреса в нодах выдачи и отправки пустыми. Явно прописанный в старой копии адрес имеет приоритет. Проверьте обе ветви отчёта.
2. В **Настройки → Принтер по умолчанию** выберите очередь Windows. У штатной ноды включите **Принтер из настроек**. Размер и положение этикетки задаются в **Настройки → Настроить печать этикеток…**. Для TSC TE310 штатный ZPL рассчитан на 25 × 13 мм. Если в ноде сохранён собственный макет, проверьте также его параметры.
3. В **Этикетки → Тестовая этикетка** выберите нужный макет и нажмите **Тестовая печать**. Программа отправит одну этикетку с нулями. Проверьте края штрихкода и считайте его сканером.
4. В **Настройки → Журнал выполнения** включите **Сохранять журнал каждого запуска в файл**. На тестовом стенде проведите полный успешный прогон и отдельно проверьте отказ до получения номера, отказ после него и ручную остановку. Сверьте, что питание снято во всех предусмотренных сценариях. Для проверки отказа используйте согласованный тестовый сервер и тестовое изделие.
5. Для одного успешного прогона сверьте модель, идентификатор, полный номер из журнала, номер в локальной копии и историю на сервере. Сравните их с текстом на этикетке и считайте штрихкод. Для коммутатора дополнительно сравните MAC на DUT и на этикетке. Для раннего отказа платы проверьте служебную запись и отсутствие печати.
6. Сохраните проверенный профиль. В **Настройки → Профили тестирования → Папка с JSON-профилями** найдите рабочую папку. Передайте на другой стенд JSON профиля и соответствующую запись `catalog/equipment-models.json` с тем же ID. Если каталог уже есть, объедините записи по ID. Проверенный профиль кладётся на верхний уровень папки профилей.
7. При необходимости передайте внешние утилиты и скрипты и проверьте их пути. Изображение и области платы, оборудование и настройки консоли сохранены в профиле. Исходные PNG и шаблоны JSON для повторного использования храните вместе в справочной папке `reference/boards`. Общая очередь принтера, адрес сервера и параметры рабочего места настраиваются на каждом стенде.

## Если проверка не проходит

| Что видно | Что сверить |
| --- | --- |
| Модели или профиля нет на другом стенде | Активную папку профилей, наличие JSON в её верхнем уровне и совпадение ID модели с записью в `catalog/equipment-models.json`. |
| Сервер возвращает номер чужой серии | Выбранную модель над графом, флажок справочника, серверный тип в журнале и диапазон. Проверьте выдачу на тестовом сервере до записи MAC и печати. |
| Отчёт RTL не принят | Сессию лаунчера, серверный адрес, путь запроса, числовой тип и переменную идентификатора платы. Проверьте сообщение о доставке и локальную копию. |
| Область платы остаётся серой | Совпадение кода области с полем ноды, включённость ноды и прохождение всех связанных проверок. |
| Штрихкод выходит за размер | Макет ноды или общий шаблон, фактический размер бумаги, левый край и параметры штрихкода. После правки напечатайте пробу и проверьте её сканером. |
