# Карта актуальности

Эта заметка фиксирует, с чем сверялась Obsidian-документация при актуализации.

## Решение

`TestBuilder.slnx` содержит только:

| Проект | Назначение |
|---|---|
| `TestBuilder/TestBuilder.csproj` | Avalonia desktop-приложение. |
| `TestBuilder.Tests/TestBuilder.Tests.csproj` | xUnit-тесты runtime, serialization и monitoring. |

Удаленные Nodify-демо `Nodify.Calculator` и `Nodify.StateMachine` не описываются как часть проекта.

Актуализация 2026-07-15: `Clear ARP Cache` сверена с кодом после добавления
поставляемого `arpd.bat`, поиска bat рядом с exe и нормализации `arp -d` в
`arp -d *`.

Актуализация 2026-07-15: технические `Body Start` и `Body End` сверены после
добавления `Clone()` для копирования составных нод с вложенным body graph.

Актуализация 2026-07-15: сохранение профилей сверено после добавления состояния текущего
JSON-файла, команды `NewProfileCommand` и прямой перезаписи загруженного профиля без повторного
диалога Save As.

Актуализация 2026-07-15: `Selftest Check` сверен после добавления повторных попыток получения
`<selftest>` в пределах `TimeoutMs`, fallback с headless Chrome/Edge на обычный HTTP и отдельного
контекстного поля `SelfTest.Attempts`.

Актуализация 2026-07-16: `Selftest Check` сверен после расширения извлечения XML из DOM:
поддержаны `<selftest>` и legacy `<settings>`, HTML/URL/JS-экранированные фрагменты LuCI и
проверка stdout headless Chrome/Edge даже при таймауте процесса. Для LuCI/deviceinfo URL также
добавлен fallback на старый `http://host/test.shtml`, ограничение browser timeout внутри попытки
и миграция старых коротких DUT selftest timeout до эффективных `160000` мс. Получение DOM перенесено
внутрь ноды через DevTools Protocol, а legacy-запись `selftest.txt` заменена хранением `SelfTestRaw`
в `TestContext`. При дублях selftest-полей приоритет отдан верхнему уровню XML, а `Subtest`
теперь возвращает `False` и помечает `HasCriticalError` вместо `InvalidOperationException` на
штатном провале вложенного графа.

Актуализация 2026-07-17: `Selftest Check` сверен после добавления настраиваемого
`PollIntervalMs`/`pollIntervalMs` для повторных запросов страницы и более подробного логирования
проверки `ValidationRules` с контекстными счетчиками `SelfTest.CheckedRuleCount`,
`SelfTest.FailedRuleCount` и `SelfTest.ValidationSummary`.

Актуализация 2026-07-17: настройки и HTTP-ноды сверены после добавления общего
`Server base URL`. Плейсхолдеры `SERVER_BASE_URL`/`server-address` в профилях больше
не резолвятся как DNS-хосты: `Get Serial Number` и `Send Test Report` берут адрес из
настроек или завершаются понятной ошибкой, если адрес не задан.

Актуализация 2026-07-15: Modbus-проверки сверены после добавления опционального
`LiveRead` для прямого чтения регистров, а `Subtest` - после добавления
`RunOnFailure` для аварийного cleanup после провала, остановки или исключения запуска.

Актуализация 2026-07-15: `GraphEditorView` сверен после добавления GUI-подсказок
в заголовки всех нод через общий `NodeHeaderHelpTemplate` и `NodeHelpTextProvider`.

Актуализация 2026-08-17: вкладка `Modbus` сверена после перехода с раскрывающихся
карточек всех устройств на master-detail интерфейс: список slave слева, регистры
выбранного устройства в единой таблице, поиск и фильтры.

Актуализация 2026-08-17: к базе знаний добавлены реестр решений, backlog,
статус проекта и журнал проверок. Их записи отделяют подтверждённые факты о
коде от кандидатов будущих работ и от субъективной оценки готовности.

Актуализация 2026-08-20: `NodeViewModel`, общий шаблон заголовка ноды и JSON
профили сверены после добавления выбора одного из семи цветов для каждой ноды.
Выбор копируется вместе с нодой и сохраняется в поле `color`.

Актуализация 2026-08-20: добавлена `Configure Network Adapters`: runtime-нода
назначает постоянные IPv4-адреса Windows-картам по имени или MAC через `netsh`,
передает диагностику в `TestContext` и используется перед `Run Data Test` в
профиле `PSW_UPS_Box_8x2Pro_full_algorithm_polling.json`.
Селектор `Auto=Switch` выбирает Ethernet-карты без IPv4-шлюза, а карта с
маршрутом по умолчанию защищена от изменения.

## Проверка после актуализации

Контрольные команды:

```powershell
rg -n "Nodify\.Calculator|Nodify\.StateMachine|Examples/Nodify" TestBuilder.slnx TestBuilder TestBuilder.Tests
dotnet build TestBuilder.slnx
dotnet test TestBuilder.slnx --no-build
```

Ожидаемый результат:

- поиск проектных ссылок на удаленные демо ничего не находит;
- сборка проходит без ошибок;
- тесты проходят без ошибок;
- предупреждения сборки не связаны с удаленными Nodify-демо.

В самих заметках точечные упоминания этих демо допустимы только как историческое пояснение, что они удалены и не входят в решение.
