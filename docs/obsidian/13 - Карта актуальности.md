## Выбор адреса в записи Modbus — 2026-11-10

«Запись регистра» предлагает адреса из оборудования профиля. Ручное поле
доступно без списка. При отсутствии карты найденные устройства появляются
после обнаружения. «Тип регистра» предлагает области Holding и Coil.
См. [[05 - Справочник нод]] и [[07 - Modbus и мониторинг]].

## Единый источник профилей — 2026-11-10

Редактор и пульт показывают JSON верхнего уровня папки из настроек. При запуске
приложение читает её содержимое. Упаковщик помещает выбранные файлы прямо в
`profiles`. См. [[06 - JSON профили]] и [[28 - Сборка и публикация обновления]].

## Контраст текста внутри нод — 2026-11-10

Шаблон нод использует цвет текста текущей темы для вложенных подписей.
Проверяются поля нод, прогресс и выключенные подтесты при смене темы.
См. [[10 - Настройки логирование тесты]].

## Удаление профилей — 2026-11-10

Команда в контекстном меню переносит JSON в `deleted` после подтверждения.
Папка `deleted` хранит файлы для восстановления вне списка профилей.
См. [[03 - Работа с приложением]] и [[06 - JSON профили]].

## Панель управления графом — 2026-11-10

Название устройства выбирается из справочника. Кнопка «+» открывает карточку
для добавления модели. Старое название вне справочника сохраняется в профиле.
Рядом с устройством указан полный диапазон серийных номеров.
Над графом доступны «Состав отчёта…» и «Справочник». В справочнике можно
открыть карточку изделия и выбрать вариант этикетки, если он задан для модели.
«Пинг» и «Аварийные действия» находятся в меню «Ещё». См. [[03 - Работа с приложением]].

## Отчёты RTL при отказе — 2026-11-10

В стандартных профилях RTL включён отчёт при отказе полного прогона.
Если номер платы ещё не выдан, используется служебный идентификатор
RTL_v2 из справочника. Номер служебной записи хранится отдельно от номера
платы. См. [[06 - JSON профили]] и [[09 - HTTP сеть отчеты печать]].

## Встроенная инструкция — 2026-11-10

## Единая папка профилей и справочники — 2026-11-10

## Прямые отчёты RTL — 2026-11-10

Отчёты RTL-SW и RTL-POE используют JSON-контракт RTL_v2 без DLL. RTL-SW
передаёт выданный заранее номер, RTL-POE получает номер из ответа.
Серверные коды отчёта задаются в `reference/serials/equipment-models.json`.
См. [[05 - Справочник нод]] и [[09 - HTTP сеть отчеты печать]].

## 1.0.2-beta — поиск и тестовая печать этикеток — 2026-11-06

«Этикетки» ищет по одному идентификатору. Короткий серийный номер дополняется
смещением выбранного изделия. Успешный ответ выбирает модель и шаблон даже

настроек. «Тестовая печать» отправляет одну этикетку по выбранному шаблону

Подробности — [[03 - Работа с приложением]], [[09 - HTTP сеть отчеты печать]].

Уточнение от 2026-11-10. В поле «Тестовая этикетка» доступны шаблоны рабочего
места, модели с кодом этикетки и их комплектации из справочника. Для пробы
достаточно выбрать этикетку и принтер. Данные повтора берутся из последней
успешной обычной печати.

Штатный ZPL для TSC TE310 приведён к размеру 25 × 13 мм. Code 128 печатается
с запасом по краям. Проверка геометрии перед отправкой использует те же
данные, что предпросмотр. Общие макеты редактируются из настроек рабочего
места, строка `TYPE` убрана из штатных команд.
После фото отпечатка PSW-2G4F-Box увеличены шрифты и откалиброван левый край
этикетки TSC TE310. Штрихкод сдвинут на 16 точек влево.

`PingMonitorSettings` и редактор задают адрес, период, таймаут, включение
и отдельный показ в инженере/пульте. Панель расположена справа от логов;
для плат без настройки скрыта. Адрес по умолчанию пустой. Настройки хранятся
в корневом `pingMonitor`, копируются и участвуют в undo, но не меняют версию
подготовки. Результаты ICMP в JSON не записываются.

`IcmpPingProbe` и `PingMonitorViewModel` выполняют один отменяемый цикл без
запуска внешнего процесса. DNS и ответ имеют общий предел ожидания; смена
профиля отменяет старый запрос и исключает публикацию его результата.
Работа не зависит от COM и теста; обучение и редактор мини-графа не опрашивают
сеть. Обновлены разделы 00, 03, 04, 06, 09 и встроенная справка.

Проверки: 97 связанных тестов прошли; после уточнения заголовка логов для узкого
окна прошли 35 проверок пинга и журналов (наборы пересекаются). Включены
17 новых тестов пинга, обе темы, реальный ICMP loopback, отмена и независимость
от COM. Подробности и ограничения — [[17 - Журнал проверок#VER-059 — панель пинга, 2026-10-30]].

## Верхняя панель регистров — 2026-10-30

## Управление внутри кнопок и карточек — 2026-10-30

В `ProfileActionBar` и `RegisterIndicatorsView` настройки и удаление расположены
внутри цветной области. `ProfileCardToolTheme` задаёт одинаковый размер и
собственный фон текущей темы; увеличенные значки имеют контрастный цвет текста
независимо от цвета карточки.
В кнопке профиля элементы управления являются отдельными соседними элементами
поверх её правой части, поэтому нажатие не попадает в команду запуска.
Прозрачная область значков перехватывает клик даже при недоступной команде;
в пульте без значков и выполняемого действия она скрыта, вся кнопка активна.
Слот остановки сохранён; переключение состояния не меняет размеры. Подтверждение
удаления и запрет редактирования в пульте сохранены. Справка и раздел 03 обновлены.
Снимки интерфейса просмотрены, сборка и `git diff --check` без ошибок.

Расширенный первый запуск дал 109/111. Два отказа `StandDiscoveryTests`
(`Apk03DiscoveryKeepsItsExistingModel` и неполная RTL-карта) воспроизведены
на чистом снимке предыдущего коммита `e6d6f1f`: 4/6 прошли, те же 2 отказа.
Они не внесены индикаторами; поиск оборудования в этой доработке не менялся.
Полный набор всех тестов и физические измерения карточек не выполнялись.
