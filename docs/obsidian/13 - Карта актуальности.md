# Карта актуальности

Эта заметка фиксирует, с чем сверялась Obsidian-документация при актуализации.

## Решение

`TestBuilder.slnx` содержит только:

| Проект | Назначение |
|---|---|
| `TestBuilder/TestBuilder.csproj` | Avalonia desktop-приложение. |
| `TestBuilder.Tests/TestBuilder.Tests.csproj` | xUnit-тесты runtime, serialization и monitoring. |

Удаленные Nodify-демо `Nodify.Calculator` и `Nodify.StateMachine` не описываются как часть проекта.

Актуализация 2026-07-16: `Selftest Check` сверен после расширения извлечения XML из DOM:

Актуализация 2026-08-21: автоматическая настройка сетевых адаптеров полностью

Актуализация 2026-08-21: настройки профилей сверены после добавления

Актуализация 2026-08-21: каждая попытка `Selftest Check` приведена к алгоритму
исходной Selenium-утилиты: один headless-браузер, исходный URL, ожидание загрузки,
фиксированные 10 секунд и один снимок `PageSource`. Такие попытки повторяются по
исходному URL до 300 секунд, потому что DUT может стартовать четыре минуты.
HTTP fallback и `/test.shtml` удалены из рабочего пути; поведение закреплено тестами.

Актуализация 2026-09-01: `Run Data Test` и рабочий профиль сверены после
исправления ошибочного target `1000` на `100 Mbps`. Нода ограничивает target
100 Mbps, считает on-wire overhead Ethernet, использует Npcap send queue,
нумерованные пробы, точный BPF, capture statistics, отдельные пороги loss/TX
deficit, инфраструктурный retry и двунаправленную проверку. Новые JSON-поля
`allowedTxDeficitPercent` и `bidirectional`, а также миграция legacy bandwidth
описаны в [[06 - JSON профили]]; расчет и probe identity закреплены unit-тестами.

Актуализация 2026-09-01: состав тестовой страницы DUT сверен с текущим
`SelfTestCheckStep` и историческими `html_parse_struct`/`traverseNodeHP` из
`kotyasmol/QTstand_old`. Отдельно задокументированы все 196 имен, которые знал
legacy-парсер, динамический характер текущего XML, семантические типы, индексация,
legacy-алиасы, служебные `SelfTest.*` и способ получить точный фактический счетчик
через `SelfTest.ParsedFieldCount`; справочник находится в
[[19 - Поля тестовой страницы DUT]].

Актуализация 2026-09-01: `Get IRP Status` и `Wait Variable Until` с poll action
`GetIrpStatus` сверены после обнаруженного на DUT HTML 404. Из-за расхождения
регистра endpoint в документации/прошивках сначала запрашивается `/api/isUPS`,
при `404`/`Not Found` — `/api/isUps`. Принимаются только `0`/`1`, старое
значение output variable удаляется до запроса, а URL, HTTP status, количество
попыток и краткая причина ошибки сохраняются для диагностики. Поведение
закреплено четырьмя unit-тестами.

Актуализация 2026-09-02: после подтверждённых HTTP 404 у UPS API и 19 неуспешных
browser/selftest-попыток за 300 секунд динамический `ups_rez` исключён из
AC-переходов фактической прошивки. В универсальный `Wait Variable Until` добавлен
`HttpReachable`: HTTP 2xx сохраняет Boolean `true`, сетевые и HTTP-ошибки
повторяются до таймаута. Работа от АКБ подтверждается диапазоном `1707 =
12000..27000` мВ, ненулевым током `1708` и доступным web DUT при снятом AC.
Возврат подтверждается отключением SIMBAT после включения AC и повторной
доступностью web. `HttpGet`, `SelftestSnapshot` и специализированные UPS-ноды
сохранены для других и legacy JSON-профилей.

Проверка 2026-09-02: тесты, временно меняющие глобальный
`AppSettings.ServerBaseUrl`, выполняются в непараллельной xUnit-коллекции;
это устраняет гонку с параллельным созданием `TestViewModel` и делает полный
прогон 73/73 воспроизводимым.

Актуализация 2026-09-02 (новая схема стенда): три UPS-подтеста заменены одним
`проверка акб (упс)`. Подключение SIMBAT выполняется через `slave 17 / 1706`,
AC1 — через `slave 23 / 1200`, а тестовая страница подтверждает подключение
аккумулятора по `Dut.akb_det` в последовательности `0 → 1 → 1 → 1 → 0`.
Каждое из четырёх управляющих действий имеет Modbus read-back, каждое состояние
получается свежим `SelftestSnapshot`; старые `1210`, `ups_rez`, `1707/1708` и
`HttpReachable` из рабочего профиля удалены как артефакты прежней схемы.

Актуализация 2026-09-03: стенд подтвердил, что `akb_det` не меняется при
`slave 17 / 1706 = 1`; это зафиксировано как внешний баг прошивки. UPS-подтест
переведён на три свежих снимка `Dut.akb_voltage` с диапазоном `20..27` В:
при включённом SIMBAT и AC1, при снятом AC1 и после возврата AC1. В
`Wait Variable Until` числовой `ExpectedValue` теперь поддерживает включительный
формат `min..max`, поэтому снимки повторяются до попадания значения в диапазон
или общего таймаута.

Актуализация 2026-09-02: после `Modbus` добавлена всегда доступная вкладка
`Тестовая страница`. `SelfTestCheckStep` публикует в потокобезопасный
`SelfTestPageState` состояния загрузки/ошибки и полный набор фактических
leaf-полей XML без служебных legacy-алиасов. Новый успешный снимок атомарно
заменяет предыдущий, поэтому исчезнувшие поля не остаются в UI; при обновлении
или ошибке последний успешный снимок сохраняется с явным статусом. Поля
показываются в девяти сворачиваемых bento-категориях с крупной типографикой;
по умолчанию скрыты только PoE A/B, остальные категории открыты. Существующие элементы обновляются на месте,
что сохраняет прокрутку и раскрытие; фактические изменения подсвечиваются 5 секунд
даже в заголовке свернутой группы. Категоризация, естественная сортировка и
подсветка закреплены unit-тестами; контрольный прогон — 88/88.

## Проверка после актуализации

Контрольные команды:

```powershell
rg -n "Nodify\.Calculator|Nodify\.StateMachine|Examples/Nodify" TestBuilder.slnx TestBuilder TestBuilder.Tests
dotnet build TestBuilder.slnx
dotnet test TestBuilder.slnx --no-build
```

Ожидаемый результат:

- поиск проектных ссылок на удаленные демо ничего не находит;
- сборка проходит без ошибок;
- тесты проходят без ошибок;
- предупреждения сборки не связаны с удаленными Nodify-демо.

В самих заметках точечные упоминания этих демо допустимы только как историческое пояснение, что они удалены и не входят в решение.
