## Проверки этой ревизии

Сборка приложения, ProfileLayout и тестового проекта завершилась успешно.
Запущен существующий набор с фильтром:

```sh
dotnet test TestBuilder.Tests/TestBuilder.Tests.csproj --no-restore -m:1 \
  --filter 'FullyQualifiedName~GuideAndHardware_AreUsableInBothThemes|FullyQualifiedName~ProfilePreparationPlanTests|FullyQualifiedName~FullProfileSerializationTests|FullyQualifiedName~ConsoleDiscoveryTests'
```

Результат: **34 пройдено, 0 ошибок, 0 пропущено**. В справочном UI-тесте
исправлено устаревшее ожидание 52 статей на фактические 54; проверка по каждому
типу ноды сохранена. Экспорт HTML и отображение справки проверены в обеих темах.
Сохраняются предупреждения NU1701, nullable, CS1998 и AVLN3001.
Полный набор всех тестов в рамках документационного аудита не запускался.

Проверены 37 Markdown-файлов и 277 локальных/wiki-ссылок: ошибок нет.
JSON справки и всех 13 рабочих/примерных профилей разбираются; `git diff --check`
без замечаний. Подробности — [[17 - Журнал проверок]]. Физические COM, DUT, Npcap и принтер
этим запуском не использовались, производственный отчёт не отправлялся.

## Что остаётся неподтверждённым или ограниченным

- Живой серверный поиск этикетки по MAC и реальные поля его ответа; код допускает
  ожидаемый формат и отклоняет неполный/неоднозначный результат.
- Аппаратное исправление К5 RTL, текущая физическая печать и полная приёмка
  каждого профиля. Имитации и старые успешные прогоны этого не доказывают.
- В `parallel_start` отключён SFP; в Pro остаются отмеченные в заметке 21
  ограничения измерений PoE/UPS/первого нагревателя. Методики этим аудитом не менялись.
- Разрешённые ресурсы параллельных ветвей и новые протоколы задаются в коде;
  формулировка «вообще ничего не зашито в коде» была бы неверной.
- `tools/ProfileLayout` проверяет корень и тела составных нод; мини-графы
  quickActions текущим обходом автоматически не измеряются.
- Версия исходников, версия запускаемого exe и локальные настройки стенда —
  разные факты. Дата этой страницы не подтверждает автоматическое обновление exe.

## Правило обновления

При изменении поведения правьте соответствующий тематический раздел и встроенную
статью. В эту карту добавляйте источник проверки и её границы; результаты запусков
с датами храните в журнале. Не вставляйте в руководство новый порядок рядом
с отменённым без удаления или явной пометки исторического варианта.
