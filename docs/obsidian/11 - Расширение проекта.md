# Расширение проекта

Эта страница описывает, как добавить новую ноду или изменить существующую без поломки редактора, runtime и JSON-профилей.

## Что нужно для новой ноды

Обычно новая нода требует четыре слоя:

1. `Domain/Steps/*Step.cs` - runtime-логика.
2. `ViewModels/StepVM/*NodeViewModel.cs` - визуальная нода, параметры, коннекторы.
3. `GraphCompiler` - создание step и привязка переходов.
4. `GraphSerializer` + `GraphDto.NodeDto` - сохранение и загрузка параметров.

Для полноценного UI также нужно:

5. `NodeTemplateSelector` - шаблон ноды.
6. `GraphEditorView.axaml` - XAML-шаблон.
7. `TestViewModel.AvailableNodes` и `BuildNodePaletteCategories()` - добавить в палитру.
8. Unit-тесты.
9. Obsidian-документация: минимум [[05 - Справочник нод]], [[06 - JSON профили]] и при необходимости [[09 - HTTP сеть отчеты печать]] или [[07 - Modbus и мониторинг]].

## Шаг 1. Runtime step

Создать класс:

```csharp
public sealed class MyStep : ITestStep
{
    public async Task<StepResult> ExecuteAsync(
        TestContext context,
        CancellationToken cancellationToken)
    {
        cancellationToken.ThrowIfCancellationRequested();
        return StepResult.True;
    }
}
```

Рекомендации:

- Логировать начало и результат.
- Не блокировать поток синхронным I/O.
- Уважать `cancellationToken`.
- Для долгих циклов вызывать `await context.WaitWhilePausedAsync(cancellationToken)`.
- Все диагностические результаты писать в `context.Variables`.
- Если есть параметр `FailOnError`, явно описать, когда шаг возвращает `False`, а когда `True` с записанной ошибкой.

## Шаг 2. NodeViewModel

Минимальный шаблон:

```csharp
public partial class MyNodeViewModel : NodeViewModel
{
    [ObservableProperty] private string parameter = "default";

    public ConnectorViewModel In { get; }
    public ConnectorViewModel TrueOut { get; }
    public ConnectorViewModel FalseOut { get; }

    public MyNodeViewModel()
    {
        Title = "My Node";
        In = new ConnectorViewModel { Title = "In", Parent = this };
        TrueOut = new ConnectorViewModel { Title = "True", Parent = this };
        FalseOut = new ConnectorViewModel { Title = "False", Parent = this };
        Input.Add(In);
        Output.Add(TrueOut);
        Output.Add(FalseOut);
    }

    public ITestStep CreateStep(ILogger logger) =>
        new MyStep(logger, Parameter);

    public override NodeViewModel Clone() => new MyNodeViewModel
    {
        Parameter = Parameter
    };
}
```

Для Modbus-ноды лучше использовать `AddInput`/`AddOutput`, чтобы `Parent` проставлялся единообразно.

## Шаг 3. GraphCompiler

В `CreateStep` добавить:

```csharp
MyNodeViewModel my => my.CreateStep(_logger),
```

Если у ноды условные выходы, добавить в `BindTransition`:

```csharp
case MyNodeViewModel myVm:
    BindTrueFalse(sourceConnector, source, target, myVm.TrueOut, myVm.FalseOut);
    break;
```

Если нода линейная, отдельный `case` в `BindTransition` не нужен: default назначит `source.Next = target`.

## Шаг 4. JSON type и поля

В `GraphSerializer.GetNodeType` добавить:

```csharp
MyNodeViewModel => "My Node",
```

В `SerializeGraph` добавить сохранение параметров:

```csharp
case MyNodeViewModel my:
    n.MyField = my.Parameter;
    break;
```

В `NodeDto` добавить nullable поле с `JsonPropertyName`.

В `DeserializeGraph` добавить case:

```csharp
"My Node" or "MY_NODE" or "Моя нода" => new MyNodeViewModel
{
    Location = location,
    Parameter = n.MyField ?? "default"
},
```

## Шаг 5. UI-шаблон

В `NodeTemplateSelector`:

- добавить свойство `public IDataTemplate? MyTemplate { get; set; }`;
- добавить branch в `Build`.

В `GraphEditorView.axaml` добавить `NodeTemplateSelector.MyTemplate`.

Если нода простая и хватает default template, можно временно не добавлять отдельный шаблон, но параметры тогда не будут редактироваться в UI.

## Шаг 6. Палитра

В `TestViewModel.AvailableNodes` добавить prototype:

```csharp
new MyNodeViewModel()
```

В `BuildNodePaletteCategories()` добавить `Find("My Node")`.

В `AddNodeAtLocation` добавить создание:

```csharp
"My Node" => new MyNodeViewModel { Location = location },
```

## Шаг 7. Тесты

Минимальный набор:

- unit-тест step на success;
- unit-тест step на failure;
- test на `FailOnError`;
- serialization round-trip;
- graph compiler transition test, если у ноды есть `True`/`False`.

## Совместимость JSON

Правила, которые лучше не нарушать:

- Не менять существующие `JSON type`, если нет миграции.
- Не менять `ConnectorViewModel.Title`, если старые профили используют эти строки.
- Новые поля делать nullable в `NodeDto`.
- При загрузке всегда иметь дефолты.
- Для старых русских/legacy имен добавлять aliases в `DeserializeGraph`.

## Когда делать новую ноду, а когда расширять старую

Новая нода лучше, если:

- появляется новая внешняя система;
- другой тип результата;
- другой смысл переходов;
- нужны отдельные переменные контекста;
- старую ноду пришлось бы перегрузить параметрами.

Расширять старую ноду лучше, если:

- добавляется опциональный параметр;
- поведение остается тем же;
- JSON совместимость легко сохранить;
- UI не становится перегруженным.

## Контрольный список перед merge

- Нода есть в палитре.
- Нода добавляется drag/drop и командой.
- Нода клонируется.
- Нода сериализуется и десериализуется.
- Все нужные коннекторы восстанавливаются из JSON.
- `GraphCompiler` создает правильный step.
- `BindTransition` соответствует выходам.
- Step уважает cancellation.
- Step пишет понятные логи.
- Ошибки идут в `False` или управляются `FailOnError`.
- Добавлены тесты.
- Обновлен [[05 - Справочник нод]].
- Обновлен JSON-раздел [[06 - JSON профили]], если менялись поля или aliases.
- Обновлена карта актуальности [[13 - Карта актуальности]], если менялась структура проекта или список нод.
