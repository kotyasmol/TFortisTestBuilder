# Новые и актуальные профили

По запросу пользователя новизна и актуальность разделены.

- **Новый** — автоматическая плашка самого свежего открываемого профиля
  каждого изделия. Сравнивается `updatedAt`, для старых файлов — дата файла.
  Назначение production/diagnostic не подменяет эту дату. Диагностическая
  методика дополнительно подписана «Диагностический».
- **Актуальный** — самостоятельная локальная отметка человека. В редакторе
  и пульте: **ПКМ по профилю → Актуальный**. Повторное нажатие снимает отметку.
  Можно отметить сколько угодно файлов, включая несколько одного изделия.
  Новый профиль тоже может быть отмечен актуальным; тогда видны обе плашки.

В группе сначала видны отмеченные актуальными, затем новый профиль. Они
остаются видны при свёрнутой группе. Раскрытие показывает остальные файлы;
поиск и фильтр по виду изделия продолжают действовать. ПКМ не выбирает
другой профиль и не переключает открытый граф. Отметка доступна оператору
без права редактировать методику.

## Хранение

`ProfileCurrentStore`: файл `profile-current.json` в
`Environment.SpecialFolder.LocalApplicationData/TFortisTestBuilder`.
В Windows: `%LOCALAPPDATA%\TFortisTestBuilder\profile-current.json`.
Хранятся нормализованные абсолютные пути; Windows сравнивает их без учёта
регистра. Формат: `schemaVersion=1`, массив `profiles`.

Это данные текущего пользователя данного компьютера. Они находятся вне
комплекта программы и папки профилей. Экспорт JSON, копирование профиля
и обновление релиза не передают отметки на другой компьютер. Перенос всей
папки профилей в другой путь вне приложения требует отметить нужные файлы
в новом месте заново.

Отметка сохраняется при обычных правках того же файла. Переименование через
ПКМ и сохранение с выравниванием имени файла переносят её на новый путь.
Копия получает собственный путь и создаётся без отметки. Удаление через
программу снимает отметку. Обновлять граф или его дату для маркировки не нужно.

Запись атомарная, с временным файлом, синхронизацией на диск и блокировкой
между экземплярами приложения. Перед изменением состояние перечитывается,
чтобы сохранить выбор другого экземпляра. Повреждённый/неизвестный формат
не перезаписывается пустым. При ошибке сохранения интерфейс не показывает
успешную отметку. Ошибка переноса отметки при переименовании сообщается
отдельно от успешной операции с самим профилем.

## Проверки

Результат 2026-11-16: 71/71 целевых тестов и 45/45 обязательных проверок
`ProfileUiIntegrityTests`, `RussianInterfaceTests`, `DataTestModeTests`.

Целевые проверки: хранение нескольких отметок, независимый локальный набор,
параллельные записи из разных экземпляров, повреждённое состояние, оба ПКМ
в двух темах, открытый граф с несохранённой правкой, копирование, переименование,
сохранение с новым именем, удаление и ошибка записи. Файлы профилей и их даты
при изменении отметок проверяются на неизменность. Контролируется отсутствие
наложений плашек на дату, снимки редактора и пульта просмотрены.

Проверки пульта используют временные профили вместо имён старой поставки.
Алгоритмы производственных профилей, DataTest, Modbus и сервер не менялись.
