# Настройки, логирование и тесты

## Настройки приложения

`AppSettings` хранит:

| Поле JSON | Свойство | Дефолт |
|---|---|---|
| `graphsFolder` | `GraphsFolder` | существующий сохраненный путь; иначе репозиторная/поставляемая `profiles` |
| `theme` | `Theme` | `Light` |

Файл настроек:

```text
{AppContext.BaseDirectory}/testbuilder.settings
```

`SettingsViewModel`:

- загружает настройки при создании;
- применяет тему;
- сохраняет изменения при смене темы;
- сохраняет путь при выборе папки профилей.

`ProfileDirectoryLocator` ищет `profiles` вверх от `AppContext.BaseDirectory`
и текущего рабочего каталога. Репозиторная папка распознается по соседнему
`TestBuilder.slnx`. Если рабочая копия не найдена, используется `profiles`
рядом с exe; `TestBuilder.csproj` копирует туда отслеживаемый рабочий JSON при
build и publish. Существующая доступная пользовательская папка не заменяется.

## Темы

Темная/светлая тема задается:

```csharp
Application.Current.RequestedThemeVariant =
    dark ? ThemeVariant.Dark : ThemeVariant.Light;
```

В `App.axaml` подключены:

- `FluentTheme`;
- DataGrid Fluent styles;
- `Assets/ModernTheme.axaml`;
- `Nodify/Theme.axaml`.

## Логирование

`LoggingService` - singleton:

```csharp
LoggingService.Instance.CreateLogger("Testing")
```

`ILogger` содержит:

- `Category`;
- `ObservableCollection<LogEntry> Entries`;
- методы `Trace`, `Debug`, `Info`, `Warning`, `Error`;
- `Clear()`.

`LogEntry` содержит timestamp, level, category, message и optional highlight color.

Подсветка определяется по тексту:

| Содержимое сообщения | Цвет |
|---|---|
| `[OK]` | зеленый |
| `[ОШИБКА]` | красный |
| `[ШАГ]` | синий |
| другое | тема UI |

Коллекция логов ограничивается 1000 записями.

## Где используются логи

| Категория | Использование |
|---|---|
| `Testing` | Основной запуск графа, шаги, Modbus status, ошибки. |
| UI log panel | `LogPanelView` показывает `TestingLogger.Entries`. |
| Modbus tab | Правая панель вкладки `Modbus` тоже показывает `TestingLogger.Entries`. |

## Тестовый проект

`TestBuilder.Tests` содержит xUnit-тесты.

### StepTests

| Файл | Что проверяет |
|---|---|
| `CheckVariableStepTests.cs` | Равенство переменных, диапазон, MAC normalization, versions, boolean aliases. |
| `CompareStepTests.cs` | `CheckRegisterRangeStep` по `RegisterState` и live-чтение через fake `IModbusService`. |
| `DelayStepTests.cs` | Реальная задержка не меньше указанной. |
| `ModbusWriteStepTests.cs` | Запись без read-back, verification retry, update `RegisterState`. |
| `ProductionStepTests.cs` | Серийник, UPS API, UDP packet, DataTest packet, packet count, unsupported mode. |
| `SelfTestCheckStepTests.cs` | Парсинг selftest, сохранение полей, fail по rules, подсети IPv4, распознавание и параметры формы LuCI. |
| `SubtestStepTests.cs` | Disabled subtest, completed body, failed body, stop-on-error. |

### Services

| Файл | Что проверяет |
|---|---|
| `HttpRequestServiceTests.cs` | Распознавание private/local адресов и выбор прямого HTTP-клиента без proxy. |

### SerializationTests

| Файл | Что проверяет |
|---|---|
| `SubtestSerializationTests.cs` | Сериализация/десериализация `Subtest`, `bodyGraph`, `runOnFailure` и `liveRead` для Modbus-проверки. |
| `ProfileDirectoryLocatorTests.cs` | Поиск репозиторной папки профилей из вложенного build-каталога и обязательность маркера решения. |

### MonitoringTests

| Файл | Что проверяет |
|---|---|
| `RegisterMonitorTests.cs` | `RegisterState.Update` и `TryGet` по slave/address. |

## Запуск тестов

```powershell
dotnet test
```

Для проверки решения целиком:

```powershell
dotnet build TestBuilder.slnx
```

На 2026-08-21 сборка проходит без ошибок, `dotnet test TestBuilder.Tests/TestBuilder.Tests.csproj --no-restore`
проходит 80/80 тестов. Известные предупреждения остаются: `NU1701` по `NModbus4`,
nullable-предупреждения в нескольких классах и `AVLN3001` для диалогов Avalonia
без публичного конструктора.

История конкретных запусков, их границы и ожидающие ручные проверки ведутся в
[[17 - Журнал проверок]].

## Что хорошо покрыто

- Изолированная логика переменных.
- Формат UDP set MAC packet.
- Формат Ethernet/UDP packet для DataTest.
- Расчет числа пакетов для DataTest.
- URL-building для серийника.
- Selftest validation.
- Поведение `SubtestStep`.
- Поведение `RegisterState`.
- Live-чтение `CheckRegisterRangeStep` через fake `IModbusService`.

## Что стоит покрыть дополнительно

- `GraphCompiler.BindTransition` для всех нод.
- Сериализация всех типов нод, не только `Subtest`.
- Live-чтение для `CheckRegisterEqualityStep`, `WaitUntilStep` и `PollRegisterStep`.
- `ForEachSlaveStep` с вложенным графом.
- `WaitVariableUntilStep` для всех poll actions.
- `BuildMacFromSerialStep`.
- `BuildTestReportStep`.
- `PrintLabelStep` хотя бы до генерации ZPL без отправки в spooler.
- `SendTestReportStep` через fake HTTP handler.
- Ошибочные JSON-коннекторы и совместимость legacy connector names.
- `BuildTestReportStep`: сейчас документация фиксирует, что step возвращает `True`; тест поможет защитить это поведение или осознанно поменять его.
