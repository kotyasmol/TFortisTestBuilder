TFortisTestBuilder - desktop-приложение на .NET 8 и Avalonia для визуальной сборки и запуска производственных тестов оборудования. Пользователь собирает сценарий как граф нод, подключается к стенду по COM/Modbus RTU, запускает граф, а приложение выполняет Modbus-операции, HTTP-запросы, сетевые проверки, операторские действия, печать этикеток и отправку отчета. Независимые проверки можно запускать параллельно через ветвление графа.

Главная идея проекта: визуальная нода в редакторе не исполняется сама по себе. Она хранит параметры и коннекторы, затем компилируется в `TestNode`, внутри которого лежит runtime-шаг `ITestStep`. Шаг возвращает `StepResult`, а исполнитель выбирает следующий переход: `Next`, `True`, `False` или `Stop`.

Термины стенда: **старые коммутаторы** — модели без `Pro`, **новые** — модели
с `Pro`. Первой в TestBuilder добавили новую модель `PSW+UPS-Box 8x2Pro`;
`PSW-2G6F+` относится к старым. Их профили используют разные страницы
selftest и способы записи MAC, поэтому параметры нод нельзя переносить между
ними без проверки модели. См. [[06 - JSON профили]] и [[12 - Глоссарий]].

## Самые важные понятия

| Понятие | Что означает |
|---|---|
| `NodeViewModel` | Визуальная нода в редакторе Nodify: заголовок, позиция, коннекторы, параметры UI. |
| `ITestStep` | Исполняемый атомарный шаг теста. |
| `TestNode` | Узел runtime-графа, содержит `Step`, `Next`, `OnTrue`, `OnFalse`. |
| `GraphCompiler` | Преобразует `GraphWorkspaceViewModel` в `CompiledGraph`. |
| `TestExecutor` | Выполняет `TestNode` по результатам `StepResult`. |
| `TestContext` | Общий контекст запуска: регистры, переменные, текущий slave, observer, операторский prompt. |
| `RegisterState` | Потокобезопасное хранилище последних известных значений регистров. |
| `GraphSerializer` | Сохраняет и загружает графы в JSON-профили. |
| `For Slaves` | Составная нода, выполняющая вложенный граф для диапазона Modbus slave ID. |
| `Subtest` | Составная нода для логического подтеста с собственным вложенным графом. |

## Текущий функциональный охват

Проект уже реализует:

- визуальный редактор графа на NodifyAvalonia;
- палитру нод с категориями;
- сохранение и загрузку JSON-профилей;
- вложенные графы для `Subtest` и `For Slaves`;
- параллельные ветви через обычные связи графа с автоматическим ожиданием всех ветвей в общей следующей ноде;
- undo/redo для базовых операций графа;
- запуск, паузу, продолжение и остановку теста;
- подсветку текущей и ошибочной ноды;
- подключение к Modbus RTU стенду через COM;
- проверку состава оборудования выбранного профиля на открытом COM-порту;
- фоновый мониторинг регистров;
- авто-восстановление Modbus-соединения при критических ошибках;
- HTTP selftest и API-запросы к DUT/серверу;
- вычисление MAC из серийного номера;
- запись MAC коммутаторов Pro через `set_mac_pro.bat` и поставляемый portable WinSCP;
- программный DataTest через SharpPcap/Npcap;
- сбор и отправку построчного отчета в формате `QTstand_old`;
- печать четырех этикеток TSC TE310 с полным серийным номером;
- вкладку «Этикетки» для ручной печати и повторной печати;
- настраиваемые кнопки профиля с отдельными графами и переключателями;
- верхнюю сворачиваемую панель регистров с масштабом карточек 50–150%;
- настраиваемую панель ICMP-пинга справа от логов и, по выбору, в пульте;
- редактор сетевого плана и пар DataTest;
- автосохранение расположения панелей и фильтра изделий;
- отправку отчета на сервер и локальную копию;
- набор unit-тестов для ключевых шагов.

На уровне палитры сейчас доступно 30 нод в 6 категориях. Еще 2 технические ноды (`Body Start`, `Body End`) создаются внутри тела `For Slaves` и не добавляются из общей палитры. Неиспользуемые `Check Register Equality`, `Poll Register` и три специализированные legacy-ноды UPS/IRP удалены из проекта; старые профили с ними отклоняются с подсказкой замены. Датчики проверяются обычными `Write Register` и `Wait Variable Until`; отдельная нода IO-2 удалена. В PSW-2G6F+ проверяется только сухой контакт Sensor1, в профиле Pro — Sensor1/Sensor2.

## Важные ограничения

- Ноды проверки регистров (`Проверка диапазона`, `Ожидание значения`) по умолчанию читают последнее значение из `RegisterState`. При `LiveRead=true` они читают Modbus напрямую; `Проверка диапазона` дополнительно поддерживает повторные чтения с паузой.
- `ModbusWriteStep` пишет напрямую через `IModbusService`; при включенной проверке записи он дополнительно читает регистр и обновляет `RegisterState`.
- `For Slaves` обходит арифметический диапазон slave ID либо повторяет тело на текущем slave (`RepeatOnSameSlave`). Для произвольного списка адресов нужны несколько циклов или отдельные ноды.
- `WaitVariableUntil` умеет как опрашивать произвольный endpoint в `HttpGet`, так и заново снимать всю тестовую страницу в `SelftestSnapshot`; старые специализированные poll actions удалены.
- RAW-печать в `PrintLabel` работает только на Windows, потому что использует `winspool.drv`.
- `Build Test Report` возвращает `False`, если в настройках нет `Stand ID`
  или в контексте нет полного положительного `SerialNumber`.
- У нод с флагом обработки ошибок снятая галочка продолжает обычный путь; непройденный пункт сохраняется в отчёте. Для selftest `FailOnError=false` теперь также даёт `True`.
