# Подготовка сетевого стенда

Один релиз программы устанавливается через beta-лаунчер на все рабочие места.
Настройки COM, принтера и соответствие кабелей сетевым картам остаются местными.
Приложение и проверочные сценарии не заменяют системные драйверы автоматически.

## 1. Собрать сведения

1. Завершите проверку изделия. Откройте папку установленной программы
   `C:\FortTelecom\Launcher\Beta\TFortis_Stand_Builder` либо фактическую папку
   приложения, указанную в лаунчере.
2. Дважды нажмите `Check-NetworkDrivers.cmd`. Права изменения сети не нужны.
3. Рядом появятся `network-driver-report.txt` и `network-driver-report.json`.
   В них есть модель и Hardware ID каждой физической карты, IP/GUID, INF,
   версия пакета, версия и SHA-256 фактического SYS, Npcap и библиотеки захвата.
4. Для переданного инженеру отчёта сохраняйте оба файла с именем компьютера.
   Драйверы, IP, питание, печать и серверные отчёты при сборе сведений не меняются.

Сведения о служебной карте также перечислены, но её драйвер не сравнивается
с эталоном тестовой карты. Приоритет у привязок в `testbuilder.settings`.
Если привязки ещё не сохранены, кандидат определяется по IP сетевого плана и
отсутствию IPv4-шлюза. Это предварительное определение, а не доказательство
подключения к нужному разъёму. Предупреждение об отсутствии эталона не означает
неисправность карты и не блокирует программу.

## 2. Привести компоненты к стандарту

Общие данные находятся вне кода в `reference/network/workstation-baseline.json`.
Файл переносится вместе с релизом. Сейчас задан Npcap **1.90** и проверенная
ревизия Realtek с драйвером **10.74.1128.2024**. Эталон Realtek применим только
к `PCI\VEN_10EC&DEV_8161&SUBSYS_816810EC&REV_15`.

1. Скачайте [Npcap 1.90](https://npcap.com/dist/npcap-1.90.exe) с официального
   сайта. SHA-256 указан в справочнике. Установку выполняет администратор.
2. Выберите **Install Npcap in WinPcap API-compatible Mode**. Этот режим
   заменяет прежние системные WinPcap DLL. Не копируйте DLL вручную.
3. После установки перезагрузите Windows. Запустите beta-лаунчер от имени
   администратора: это нужно также для очистки ARP и настройки адресов.
4. В приложении откройте «Сеть → Проверить компьютер». Сверьте версию и путь
   фактически загруженной библиотеки; один установленный Npcap не доказывает,
   что программа использует именно его.
5. Для карт с подходящим Hardware ID используйте указанный в справочнике
   подписанный пакет Microsoft Update Catalog. Перед заменой сохраните
   прежний драйвер и сетевые привязки; после замены повторите сбор сведений.
6. Для Intel, другого Realtek или другой ревизии подберите пакет производителя
   именно для её Hardware ID и Windows. Сначала квалифицируйте сочетание,
   затем добавьте его версию, SHA-256 SYS и источник в `networkDrivers`.
   Больший номер версии сам по себе не подтверждает пригодность для стенда.

Не применяйте пакет Realtek к Intel или к неподтверждённой ревизии Realtek.
EEE, flow control, interrupt moderation и прочие свойства карт массово не
меняются: для общего такого правила пока нет подтверждения измерениями.
Сетевой адаптер доступа к серверу не должен попадать под замену тестовых карт.

Npcap не входит в ZIP. [Официальное руководство](https://npcap.com/guide/npcap-users-guide.html)
описывает установку; тихий режим доступен в OEM. Для массовой организации
нужно учитывать [условия Npcap](https://npcap.com/oem/): свободная лицензия
ограничена пятью установками с оговорёнными исключениями. Отсутствующая OEM
лицензия не заменяется автоматической загрузкой установщика программой.

## 3. Проверить сетевое рабочее место

1. В «Сеть» выберите набор и проверьте привязки физических карт к портам.
   Названия карт не являются доказательством текущей скорости линка.
2. Нажмите «Применить адреса», затем «Проверить связь». Короткая проба проверяет
   прохождение пакетов по заданным парам в обе стороны; её нагрузка 1 Мбит/с.
3. Для квалификации генератора соедините тестовые карты напрямую известными
   парами. Запустите отдельный DataTest-профиль с фактическими парами на
   100 Мбит/с и 1000 Мбит/с для поддерживающих гигабит портов. Проверьте оба
   направления, штатную длительность и прежние допуски.
4. Выполните три полных прогона. Для квалификации рабочего места нужны успех
   с первой попытки, отсутствие ошибок генератора/захвата/карт и прохождение
   установленных порогов скорости/потерь во всех направлениях. Успех после
   повтора отмечает восстановление, но не считается доказательством устойчивого
   генератора на этом ПК.
5. Подключите изделие. Для коммутатора дождитесь загрузки — около трёх минут;
   используйте соответствующее ожидание профиля. После этого выполните
   утверждённый производственный профиль. Проводка и скорости пар должны
   соответствовать именно этой модели.
6. При неудаче сохраните полный журнал и JSON профиля вместе с отчётом о
   драйверах. По ним различаются потери тракта и недостоверный замер стенда.

Проверенная установка и одинаковые версии компонентов не гарантируют исправность
кабеля, карты или изделия. Эталонный профиль от 11.11.26 при обновлении кода
не заменяется. Описание DataTest и повтора — [[09 - HTTP сеть отчеты печать]],
порядок публикации — [[28 - Сборка и публикация обновления]].
