# Статус проекта

Состояние подтверждено чтением текущего кода и профилей. Результаты запусков
проверок приведены в [[13 - Карта актуальности]] и [[17 - Журнал проверок]].
Старая оценка «76%» от 17 августа не характеризует текущую сборку и больше
не используется как показатель готовности.

## Реализовано

| Область | Текущее состояние |
|---|---|
| Редактор и профили | 30 типов нод, вложенные тела, параллельные ветви с ограничениями, частичный запуск, копирование/переименование через ПКМ. |
| Подключение | Открытие COM отдельно от проверки оборудования профиля и подготовки при открытии. |
| Оборудование | Каталог и пользовательские карты Modbus, профильные копии, UART-консоли с правилами поиска. |
| Производственный UI | Пульт, названия операций, кнопки профиля, стабильное чтение истории логов, темы, сохранение рабочего поля. |
| Сеть и печать | Настраиваемый план адаптеров, таблица пар DataTest, шаблоны этикеток, отдельная пробная печать. |
| Платы | RTL-SW/PoE, изображения/области, консоль, внешние программы, разбор ответа и цвет LED. |
| Тесты | xUnit, fake-сервисы, Avalonia.Headless, сериализация, моделирование алгоритмов. Наличие теста не равно успешному прогону этой ревизии. |

## Ограничения

- Аппаратная приёмка зависит от конкретного профиля, ревизии изделия и схемы стенда.
  Вариант Pro без SFP не подтверждает гигабитные порты. Допуски первого нагревателя
  Pro и отсутствие отдельных PoE/UPS-условий описаны в [[21 - PSW+UPS-Box 8x2Pro тестирование]].
- Для RTL параметры перенесены из предоставленных RTL_v1. Аппаратное подтверждение
  исправления К5 отсутствует; симуляция не доказывает электрические характеристики.
- Контракт серверного поиска этикетки по MAC остаётся неподтверждённым живым
  запросом. Детали и проверяемый формат — [[09 - HTTP сеть отчеты печать]].
- Полный производственный путь требует Windows, Npcap, прав на COM/сетевые настройки,
  принтера и доступа к серверу/сессии. Сборка на Mac это не проверяет.
- Не все внутренние правила редактируются через UI: например, ограничения
  ресурсов параллельных ветвей реализованы в `ParallelResourceValidator`.
  Новые протоколы, типы нод и неподдерживаемые аппаратные операции требуют кода.
- Автосохранение касается интерфейса, а не несохранённых графов. Настройки лежат
  рядом с приложением и требуют права записи в эту папку.

## При следующей приёмке

Зафиксировать ревизию кода, копию профиля, состав оборудования, настройки сети,
результат полного прогона и физическую печать. Отдельно проверить отказ,
остановку, завершающие действия и восстановление связи. Запись проверки должна
содержать дату и ограничения, а не только число прошедших программных тестов.
