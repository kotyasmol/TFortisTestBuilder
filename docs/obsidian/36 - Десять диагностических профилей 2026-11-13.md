# Десять диагностических профилей

Набор находится в `examples/profiles/Проверка 10 моделей`. В него входят
PSW-1G4F, PSW-2G4F, PSW-2G6F+, PSW-2G8F+, PSW-2G4F-Box,
PSW-2G6F+Box, PSW-2G8F+Box, PSW-2G8F+Ex, PSW+UPS-Box 8x2Pro
и PSW+Box 8x2Pro. Имена файлов совпадают с интерфейсом и содержат 13.11.26.
Четыре базовых профиля в `profiles` не изменены.

Для просмотра выбрать эту папку в настройках профилей. Вложенная
`catalog/equipment-models.json` содержит десять полных карточек редакции
11.11.26 с `isFullOverride`: набор переносится вместе с диапазонами,
серверными типами, MAC, комплектациями и шкафами. Это снимок; последующая
правка поставляемого справочника не заменит эти локальные карточки.

Это диагностическая методика: CPU ID, допустимый тип, серверный номер,
init_ok, совпадение CPU ID после выдачи, DataTest и отчёт. У 032 ещё
ups_det=1. Новые аппаратные допуски и минимальные версии не выдумывались;
нагреватели, силовой PoE, цикл АКБ, прошивка и запись MAC не выполняются.
Печать выключена, использует одну этикетку, реальный согласованный MAC,
модель/комплектацию из справочника и общие настройки принтера/макета.

GET номера и POST отчёта используют общий сервер. Состав отчёта одинаков
для штатной и аварийной ветвей, тип проверки `diagnostic`, полный номер
обязателен. Отчёт при отказе всегда содержит причину остановки, включая
случай выбранной неуспешной булевой строки. Статус доставки и результат
изделия разделены. Принятый отчёт аварийная ветка не дублирует.
Исправлена `FailureReportPolicy`: после выдачи номера аварийный отчёт
разрешён и у моделей без служебного номера. Раньше общий флаг отправки
не учитывал уже выданный номер. Политика проверена для всех десяти моделей,
подготовки, отмены, частичного запуска и маршрута RTL.

Ранний отказ без номера: 032 использует подтверждённый 3200001, остальные
девять не отправляют на сервер до настройки подтверждённой служебной записи.
В журнале причина остаётся. У Pro dev_type=0 не различает исполнения:
оператор сверяет выбранную модель с изделием.

Автотесты используют подставной HTTP и принтер; данные DUT/DataTest
синтетические. ProfileLayout проверяет все 130 графов и 621 ноду в обеих
темах, после записи — отдельная проверка повторно загруженных JSON.
Итоговые прогоны: 249 тестов отчётов/каталога и 64 теста UI/аварийного
завершения прошли; 0 неуспешных, 0 пропущенных. Проверены все новые вложенные
редакторы без изменения параметров, SHA-256 четырёх базовых файлов не изменились.
АПК‑03 и Вышенская при подготовке offline: Windows, настоящий сервер и
10 физических устройств ещё не проверены. Релиз не публиковался.
