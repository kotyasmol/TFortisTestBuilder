# Поля тестовой страницы DUT

Эта заметка описывает переменные из XML-блока `<selftest>` или legacy-блока
`<settings>`, который находится на странице `deviceinfo` коммутатора. В старой
программе эта сущность называлась «тестовая страница» или `test.shtml`.

Это **не** список параметров нод на вкладке `Test` и не полный список всех
переменных `TestContext`. Здесь описаны именно данные, которые возвращает DUT.

## Короткий ответ про «82 поля»

Фиксированного числа `82` в протоколе и в коде нет.

- Текущий `SelfTestCheckStep` принимает **любое leaf-поле** XML и сохраняет его.
- Исторический Qt-парсер знал 196 возможных имен: скалярные поля и семейства для
  максимум 16 портов.
- Конкретная модель и версия прошивки возвращают только применимый поднабор.
- Точное число уникальных XML-полей текущего ответа записывается в
  `SelfTest.ParsedFieldCount` и выводится в лог как `Selftest passed: N fields`.

Для страницы с `L` link-полями, `P` PoE-портами, `S` SFP-портами и `I`
дискретными входами ориентировочное число при наличии всех скалярных полей:

```text
26 + L + 6*P + 3*S + I
```

На реальном DUT 2026-09-01 лог подтвердил `Selftest passed: 82 fields`.
Это фактическое число для данной модели/прошивки, но его нельзя использовать
как обязательную константу или критерий успеха.

## Как поля попадают в TestContext

При стандартном `OutputPrefix = Dut` каждое уникальное leaf-поле превращается в
переменную:

```text
<init_ok>1</init_ok>                         -> Dut.init_ok = "1"
<default_mac>C0:11:A6:20:00:01</default_mac> -> Dut.default_mac = "C0:11:A6:20:00:01"
```

Правила текущего runtime:

- все значения, полученные из XML, сохраняются как `string`, даже если по смыслу
  это число или флаг;
- имя XML-тега сохраняется без исправлений, включая историческую опечатку
  `firmvare_vers`;
- `OutputPrefix` можно изменить; финальная нода рабочего профиля использует
  `DutFinal`, поэтому создает `DutFinal.<field>`;
- при одинаковом имени тега приоритет имеет последнее одноименное поле верхнего
  уровня `<selftest>`/`<settings>`, иначе последнее найденное leaf-поле;
- повторный `Selftest Check` перезаписывает пришедшие значения, но не очищает
  ранее созданные `${OutputPrefix}.*`, которых нет в новом ответе;
- `SelfTest.ParsedFieldCount` считает уникальные исходные XML-теги до добавления
  legacy-алиасов, поэтому число ключей `Dut.*` может быть больше.

## Вкладка «Тестовая страница»

Главное окно содержит отдельную вкладку сразу после `Modbus`. Она показывает
имя и текущее строковое значение каждого уникального leaf-поля из последнего
успешно разобранного `<selftest>`/`<settings>` в крупных сворачиваемых
bento-категориях.

- карточки используют исходные XML-имена и не включают legacy-алиасы или
  служебные `SelfTest.*`;
- категории: устройство, Ethernet, отдельные PoE A/B, SFP, питание/UPS,
  входы/датчики, климат и прочее; по умолчанию свернуты только PoE A/B;
- любой `Selftest Check`, в том числе вызванный `SelftestSnapshot`, публикует
  новый снимок в общий `SelfTestPageState`;
- новый успешный снимок полностью заменяет старый, поэтому отсутствующее в новом
  XML поле не остается на экране со старым значением;
- при старте нового теста состояние сбрасывается в «ещё не загружена»;
- во время повторной загрузки или после ошибки последний успешный снимок остается
  в карточках, но заголовок явно сообщает, что идет обновление или оно не удалось;
- неизменившиеся элементы обновляются на месте, поэтому прокрутка и раскрытие
  групп не сбрасываются; новое или изменённое значение подсвечивается 5 секунд,
  а свернутая категория показывает счетчик недавних изменений;
- если успешного снимка еще не было, вместо пустой панели отображается причина:
  страница не загружена, загружается или завершилась ошибкой.

## Полный исторический словарь

Это полный набор имен, который разбирал старый Qt-проект
[`QTstand_old`](https://github.com/kotyasmol/QTstand_old). Новый парсер не
ограничен этим словарем: неизвестное новое leaf-поле прошивки также будет
сохранено как `${OutputPrefix}.<имя>`.

### Идентификация и версии — 8 полей

| XML-поле | Переменная при префиксе `Dut` | Смысл | Формат |
|---|---|---|---|
| `dev_type` | `Dut.dev_type` | Код модели/типа устройства. | Целое число. |
| `init_ok` | `Dut.init_ok` | Сводный результат встроенной самодиагностики. В рабочем профиле норма — `1`. | Флаг/целое. |
| `firmvare_vers` | `Dut.firmvare_vers` | Версия основной прошивки. Опечатка `firmvare` является частью wire-имени. | Строка версии или число прошивки. |
| `hw_vers` | `Dut.hw_vers` | Версия аппаратной части. | Строка/число; legacy-код встречал шестнадцатеричный формат. |
| `boot_vers` | `Dut.boot_vers` | Версия загрузчика. | Строка/число; legacy-код разбирал как hex. |
| `serial_num` | `Dut.serial_num` | Серийный номер, записанный в DUT. | Целое число. |
| `default_mac` | `Dut.default_mac` | Текущий базовый MAC-адрес устройства. | MAC-строка. |
| `cpu_id` | `Dut.cpu_id` | Уникальный идентификатор CPU, используемый для получения серийного номера. | Строка. |

### Ethernet link — до 16 полей

| XML-поля | Переменные | Смысл | Формат |
|---|---|---|---|
| `link_0` … `link_15` | `Dut.link_0` … `Dut.link_15` | Состояние линка соответствующего Ethernet-порта. Историческая нумерация начинается с нуля. | Обычно `0` — link down, `1` — link up. |

Прошивка конкретной модели может прислать только реально существующие порты.

### PoE — до 96 полей

Для каждого `N = 1..16` старый парсер поддерживал шесть полей:

| XML-шаблон | Переменная | Смысл | Формат/единица |
|---|---|---|---|
| `poe_a_N_state` | `Dut.poe_a_N_state` | Состояние PoE-пары/канала A порта N. | Флаг/целое. |
| `poe_b_N_state` | `Dut.poe_b_N_state` | Состояние PoE-пары/канала B порта N. | Флаг/целое. |
| `poe_a_N_v` | `Dut.poe_a_N_v` | Измеренное напряжение канала A. | Обычно число в вольтах; legacy-тест умножал его на 1000 для сравнения в мВ. |
| `poe_b_N_v` | `Dut.poe_b_N_v` | Измеренное напряжение канала B. | Обычно число в вольтах. |
| `poe_a_N_c` | `Dut.poe_a_N_c` | Измеренный ток канала A. | Число; единица определяется прошивкой DUT. |
| `poe_b_N_c` | `Dut.poe_b_N_c` | Измеренный ток канала B. | Число; единица определяется прошивкой DUT. |

`A` и `B` — две PoE-пары/линии одного физического порта, а не направление
Ethernet-трафика.

### Плата, контроллер PoE и сухие контакты — 5 полей

| XML-поле | Переменная | Смысл | Формат |
|---|---|---|---|
| `board_version` | `Dut.board_version` | Ревизия платы. | Целое число. |
| `poe_controller` | `Dut.poe_controller` | Идентификатор микросхемы PoE-контроллера. | Целое/ID. |
| `sensor_0` | `Dut.sensor_0` | Состояние сухого контакта/датчика 0; в старом стенде использовался как датчик вскрытия. | Флаг/целое. |
| `sensor_1` | `Dut.sensor_1` | Состояние сухого контакта/датчика 1. | Флаг/целое. |
| `sensor_2` | `Dut.sensor_2` | Состояние сухого контакта/датчика 2. | Флаг/целое. |

### SFP — до 48 полей

Для каждого `N = 1..16`:

| XML-шаблон | Переменная | Смысл | Формат |
|---|---|---|---|
| `sfp_N_pres` | `Dut.sfp_N_pres` | Физическое присутствие SFP-модуля (`PRESENT`). | Обычно `0/1`. |
| `sfp_N_sd` | `Dut.sfp_N_sd` | Наличие оптического сигнала (`Signal Detect`). | Обычно `0/1`. |
| `sfp_N_id` | `Dut.sfp_N_id` | Результат идентификации/I²C-доступа к SFP. Старый тест ожидал значение `3`. | Целое/битовая маска. |

Хотя legacy-структура резервировала 16 индексов, страница обычно отдает поля
только для фактических SFP-портов модели.

### Switch-контроллер и внутренние линии питания — 6 полей

| XML-поле | Переменная | Смысл | Формат |
|---|---|---|---|
| `marvell_id` | `Dut.marvell_id` | Идентификатор switch-контроллера Marvell. | Целое/ID. |
| `adc_1_0` | `Dut.adc_1_0` | Код АЦП внутренней линии 1,0 В. | Raw ADC count. |
| `adc_1_2` | `Dut.adc_1_2` | Код АЦП внутренней линии 1,2 В. | Raw ADC count. |
| `adc_1_5` | `Dut.adc_1_5` | Код АЦП внутренней линии 1,5 В. | Raw ADC count. |
| `adc_1_8` | `Dut.adc_1_8` | Код АЦП внутренней линии 1,8 В. | Raw ADC count. |
| `adc_2_5` | `Dut.adc_2_5` | Код АЦП внутренней линии 2,5 В. | Raw ADC count. |

Старый стенд переводил raw-код в вольты множителем `0.0008056640625`. Текущий
`Selftest Check` сохраняет исходную строку и сам пересчет не выполняет.

### UPS и аккумулятор — 5 полей

| XML-поле | Переменная | Смысл | Формат/единица |
|---|---|---|---|
| `ups_det` | `Dut.ups_det` | Обнаружена плата IRP/UPS. | Обычно `0/1`. |
| `akb_det` | `Dut.akb_det` | Обнаружен аккумулятор. | Обычно `0/1`. |
| `ups_rez` | `Dut.ups_rez` | Текущий источник питания: старый тест трактовал `0` как сеть, `1` как АКБ. | Обычно `0/1`. |
| `akb_voltage` | `Dut.akb_voltage` | Измеренное напряжение аккумулятора. | Число, В. |
| `akb_voltage_chg` | `Dut.akb_voltage_chg` | Измерение аккумулятора/зарядного канала; точный физический смысл зависит от прошивки. | Число, обычно В. |

На фактической прошивке обнаружен баг: `Dut.akb_det` не меняется после записи
`slave 17 / 1706 ← 1`, поэтому рабочий профиль не использует его как критерий.
После подключения SIMBAT, после отключения AC1 и после возврата AC1 снимается
новая страница и `Dut.akb_voltage` должен находиться во включительном диапазоне
`20..27` В. `Dut.ups_det` по-прежнему означает наличие платы UPS/IRP, а
`ups_rez` остаётся legacy-признаком источника питания.

### Дискретные входы — до 10 полей

| XML-поля | Переменные | Смысл | Формат |
|---|---|---|---|
| `input_0` … `input_9` | `Dut.input_0` … `Dut.input_9` | Состояния входов Teleport/TLP. | Обычно `0/1`. |

### Климат — 2 поля

| XML-поле | Переменная | Смысл | Формат/единица |
|---|---|---|---|
| `temperature` | `Dut.temperature` | Температура по данным DUT. | Число; единица определяется прошивкой, обычно °C. |
| `humidity` | `Dut.humidity` | Относительная влажность по данным DUT. | Число; обычно %. |

## Проверка подсчета исторической схемы

| Группа | Максимум полей |
|---|---:|
| Идентификация и версии | 8 |
| Ethernet link | 16 |
| PoE: 6 полей × 16 портов | 96 |
| Плата, PoE-контроллер, датчики | 5 |
| SFP: 3 поля × 16 индексов | 48 |
| Switch-контроллер и внутренние питания | 6 |
| UPS и АКБ | 5 |
| Дискретные входы | 10 |
| Температура и влажность | 2 |
| **Всего возможных имен в legacy-парсере** | **196** |

Это емкость исторического парсера, а не требование к одной странице.

## Legacy-алиасы, создаваемые новым runtime

Для совместимости `SelfTestCheckStep` дополнительно создает следующие ключи.
Они не являются отдельными полями страницы.

| Исходное XML-имя | Дополнительный ключ при `OutputPrefix = Dut` |
|---|---|
| `link_N` | `Dut.link[max(0, N-1)]` |
| `poe_a_N_state`, `poe_a_state_N`, `poe_a_N_st` или `poe_a_st_N` | `Dut.poe_a_st[N-1]` |
| Те же четыре формы с `poe_b` | `Dut.poe_b_st[N-1]` |
| `poe_a_N_v` или `poe_a_v_N`; те же формы с `poe_b` | `Dut.poe_a_v[N-1]` или `Dut.poe_b_v[N-1]` |
| `poe_a_N_c` или `poe_a_c_N`; те же формы с `poe_b` | `Dut.poe_a_c[N-1]` или `Dut.poe_b_c[N-1]` |
| `sfp_N_pres`, `sfp_N_sd`, `sfp_N_id` | `Dut.sfp_pres[N]`, `Dut.sfp_sd[N]`, `Dut.sfp_id[N]` |
| `sfp_pres_N`, `sfp_sd_N`, `sfp_id_N` | Те же `Dut.sfp_*[N]`. |

Для новых графов следует использовать канонические имена из XML, например
`Dut.poe_a_1_state`, а не алиасы с квадратными скобками. В частности,
исторические `link_0` и `link_1` оба могут дать alias `Dut.link[0]`, поэтому
канонические `Dut.link_N` безопаснее.

## Служебные переменные Selftest Check

Кроме полей DUT нода создает служебные ключи:

| Переменная | Тип | Когда появляется | Назначение |
|---|---|---|---|
| `SelfTest.Url` | `string` | После попыток получения страницы | Исходный URL ноды. |
| `SelfTest.StatusCode` | `int` | После попыток | Последний HTTP status или `0`. |
| `SelfTest.ElapsedMs` | `int` | После попыток | Полное время ожидания страницы. |
| `SelfTest.Attempts` | `int` | После попыток | Число браузерных попыток. |
| `SelfTest.PollIntervalMs` | `int` | После попыток | Фактический интервал между попытками. |
| `SelfTestRaw` | `string` | После получения результата | Извлеченный XML; при ошибке получения — пустая строка. |
| `SelfTest.ParsedFieldCount` | `int` | После успешного разбора XML | Число уникальных leaf-тегов без алиасов. |
| `SelfTest.CheckedRuleCount` | `int` | После разбора XML | Число выполненных `ValidationRules`. |
| `SelfTest.FailedRuleCount` | `int` | После разбора XML | Число проваленных правил. |
| `SelfTest.ValidationSummary` | `string` | После разбора XML | Сводка `OK/FAIL` по правилам. |
| `SelfTest.Ok` | `bool` | При завершении ноды | Итог ноды. |
| `SelfTest.Error` | `string` | При завершении ноды | Пустая строка при успехе или причина ошибки. |

Все `SelfTest.*` общие для нод с любым `OutputPrefix` и перезаписываются каждым
следующим `Selftest Check`. После финального `DutFinal` они описывают именно
последний запрос страницы.

## Что не является полем тестовой страницы

Следующие переменные рабочего профиля создаются другими нодами и не должны
считаться в `SelfTest.ParsedFieldCount`:

- `Dut.NewMac`, `SerialNumber`, `SerialShort`;
- `LastCheck.*`, `WaitVariable.*`, `HttpRead.*`, `GetIrpStatus.*`;
- `DataTest.*`;
- `TestReportJson`, `BuildReport.*`, `SendReport.*`, `PrintLabel.*`;
- `Execution.*` и прочие служебные результаты шагов.

## Как получить точный список с реального DUT

1. Запустить `Selftest Check` и найти в логе строку
   `Selftest passed: N fields`.
2. Проверить `SelfTest.ParsedFieldCount` в отчете с `Include all variables`.
3. Для аудита сохранить значение `SelfTestRaw` из `TestContext`/отчета и выписать
   уникальные leaf-теги XML.
4. Если прошивка добавила тег, которого нет в таблицах выше, дополнить эту заметку;
   менять парсер для самого сохранения нового leaf-поля не требуется.

Стендовой лог 2026-09-01 подтвердил 82 уникальных поля; сам `SelfTestRaw` для
посимвольной сверки списка тегов не сохранялся. Таблицы выше сверены с текущим
`SelfTestCheckStep` и полным legacy-парсером
`html_parse_struct`/`traverseNodeHP` из `QTstand_old`.
