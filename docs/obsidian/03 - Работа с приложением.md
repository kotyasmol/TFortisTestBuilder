# Работа с приложением

## Главное окно

`MainWindow.axaml` содержит `TabControl` с тремя вкладками:

| Вкладка | View | ViewModel | Назначение |
|---|---|---|---|
| `Тест` | `TestView` | `TestViewModel` | Редактор графа, профили, подключение, запуск, логи. |
| `Modbus` | `ModbusMonitoringView` | `ModbusMonitoringViewModel` | Список найденных устройств, регистры, Modbus-логи. |
| `Настройки` | `SettingsView` | `SettingsViewModel` | Папка профилей, Server base URL и тема. |

Вкладка `Modbus` активна только когда `MainWindowViewModel.IsSlavesFound == true`. Это значение синхронизируется с `TestViewModel.IsMonitoringActive`, то есть вкладка становится доступной после успешного сканирования и запуска мониторинга.

## Вкладка Тест

`TestView` делится на левую панель и основную область:

```text
Левая панель:
  ControlPanelView
  ProfileListView

Правая область:
  GraphEditorView
  GridSplitter
  LogPanelView
```

### ControlPanelView

Содержит:

- название приложения;
- кнопку подключения/отключения;
- кнопку запуска графа;
- статусное сообщение.

Подключение выполняет `ToggleConnectionCommand`, запуск - `RunGraphCommand`.

### ProfileListView

Содержит:

- список профилей из `AppSettings.Instance.GraphsFolder`;
- поиск по имени;
- импорт JSON-профилей.

При выборе профиля вызывается `LoadProfile(filePath)`.

`NewProfileCommand` доступна из панели профилей и верхней панели редактора. Она очищает корневой граф,
сбрасывает выбранный профиль и переводит редактор в состояние `Новый профиль`; первое сохранение после этого
открывает диалог выбора имени файла. После загрузки профиля приложение запоминает путь JSON, поэтому обычная
кнопка `Сохранить` перезаписывает текущий файл без повторного диалога. Если профиль ещё не привязан к файлу,
используется Save As.

Если сохраненная папка профилей не задана или недоступна,
`ProfileDirectoryLocator` автоматически находит `profiles` в корне репозитория.
Рабочий профиль `PSW_UPS_Box_8x2Pro_full_algorithm_polling.json` хранится там под
Git, поэтому его сохранение из UI сразу становится изменением рабочей копии.
Для опубликованного приложения тот же профиль копируется в `profiles` рядом с exe.

### GraphEditorView

Центральный редактор Nodify:

- кнопка `Назад` для выхода из вложенного графа;
- `Запустить граф`;
- `Пауза`, `Продолжить`, `Остановить`;
- `Undo`, `Redo`;
- `Новый`;
- `Очистить`;
- `Сохранить`;
- breadcrumb текущего графа;
- однотонный фон редактора без сетки;
- связи между нодами;
- сворачиваемая палитра нод справа.

В заголовке каждой ноды есть компактный значок справки с hover-подсветкой. По
клику в редакторе открывается закрепленная GUI-карточка справки: что делает
нода, как использовать ее в сценарии и за что отвечают видимые параметры.
Карточка расположена отдельным слоем поверх графа, поэтому не обрезается рамками
ноды и поддерживает прокрутку длинных описаний.

`Запустить граф` в UI требует активного подключения к стенду. Даже если граф состоит только из нод без Modbus, `RunGraphAsync` сейчас проверяет `IsConnected` перед компиляцией и выполнением.

### LogPanelView

Показывает `TestingLogger.Entries`. Лог автоматически прокручивается в code-behind и ограничивается 1000 записями на уровне `LoggingService`.

## Палитра нод

Категории формируются в `TestViewModel.BuildNodePaletteCategories()`:

| Категория | Ноды |
|---|---|
| `Структура` | `Старт`, `Конец`, `Подтест`, `Цикл For`, `Метка`, `Задержка` |
| `Modbus` | `Запись регистра`, `Проверка диапазона`, `Проверка равенства`, `Ожидание значения`, `Опрос регистра` |
| `Проверки` | `Selftest Check`, `Check Variable Equality`, `Check Variable Range` |
| `HTTP и сеть` | `Clear ARP Cache`, `Get Serial Number`, `Send UDP Set MAC`, `Run Data Test`, `Get UPS Status`, `Get UPS Voltage`, `Get IRP Status`, `Wait Variable Until` |
| `Оператор и отчеты` | `Действие оператора`, `Build MAC From Serial`, `Compare Variables`, `Build Test Report`, `Print Label`, `Send Test Report` |

Ноды можно добавлять кнопкой/командой или drag/drop из палитры. Код добавления находится в `TestViewModel.AddNodeAtLocation`.

## Работа со связями

`PendingConnectionViewModel` хранит исходный коннектор при начале протягивания и вызывает `IGraphEditor.Connect(source, target)` при завершении.

Ограничения текущей реализации:

- нельзя соединить коннектор с самим собой;
- нельзя соединить два коннектора одной и той же ноды;
- направление связи технически не валидируется строго на уровне `PendingConnectionViewModel`, но `GraphCompiler` ожидает, что source - выход, target - вход.

## Выделение и удаление

`TestView.axaml.cs` подписывается на `KeyDown` верхнего уровня:

- `Delete` удаляет выделенные ноды;
- если ноды не выделены, `Delete` удаляет выделенную связь;
- `Escape` снимает выделение связи.

Защищенные ноды:

- `Body Start` и `Body End` нельзя удалить внутри тела `For Slaves`;
- `Start` и `End` нельзя удалить в body graph `Subtest`, где не используются boundary-ноды.

## Undo/Redo

`UndoRedoManager` хранит до 50 команд:

- `AddNodeCommand`;
- `AddConnectionCommand`;
- `DeleteConnectionCommand`;
- `DeleteNodesCommand`;
- `PasteNodesCommand`.

После undo/redo вызывается пересчет `IsConnected` у коннекторов.

## Копирование и вставка

`TestViewModel.CopyNodes()`:

- берет выделенные ноды, кроме защищенных boundary-ноды;
- глубоко клонирует составные ноды;
- сохраняет связи только между выбранными нодами.

`PasteNodes()`:

- вставляет копии со смещением `30`;
- восстанавливает внутренние связи;
- выделяет вставленные ноды;
- записывает операцию в undo history.

## Вложенные графы

Открытие вложенного графа делает команда `OpenCompositeNodeBodyCommand`.

Механика:

1. Проверяется, что нода реализует `ICompositeNodeViewModel`.
2. Для `CompositeNodeViewModel` вызывается `EnsureDefaultBodyNodes()`.
3. Текущий граф кладется в `_graphStack`.
4. `CurrentGraph` заменяется на `BodyGraph`.
5. В breadcrumb добавляется имя ноды.

Возврат назад делает `GoBackGraphCommand`.

У `Subtest` внутри тела используются обычные `Start` и `End`. У `For Slaves` используются технические `Body Start` и `Body End`; обычные `Start`/`End` в такое тело добавить нельзя.

## Вкладка Modbus

`ModbusMonitoringView` показывает:

- кнопку `Сканировать`;
- состояние подключения;
- состояние сканирования;
- состояние мониторинга;
- компактный список найденных slave-устройств слева;
- таблицу регистров выбранного устройства в центральной области;
- поиск регистра по адресу или названию, фильтр категории и фильтр writable-регистров;
- логи Modbus.

Двойной клик по writable-регистру открывает диалог записи регистра (`WriteRegisterDialog`).

## Настройки

`SettingsView` управляет:

- папкой JSON-профилей;
- общим `Server base URL` для профилей с плейсхолдером `SERVER_BASE_URL`;
- светлой/темной темой.

Ручной выбор папки остается доступен и имеет приоритет, пока выбранный каталог
существует. Автоматический fallback нужен для нового клона репозитория и для
переноса рабочей копии между macOS и Windows без абсолютных путей в Git.

Тема применяется через `Application.Current.RequestedThemeVariant`.
