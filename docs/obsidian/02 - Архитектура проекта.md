# Архитектура проекта

## Пульт и контракт лаунчера (2026-10-01)

`LauncherOptions` разбирает session ID и имя; `App` хранит их только в памяти.
Режим интерфейса хранится в `AppSettings.EngineerMode` (по умолчанию `false`).
`SettingsViewModel` сохраняет выбор; `MainWindowViewModel` сразу переключает
`StationDashboardView` и инженерные вкладки с тем же `TestViewModel`. Кнопка
«Настройки» доступна в обоих режимах; изменение режима блокируется во время
проверки, cleanup и подключения, в том числе при прямой записи свойства VM.

Оба представления используют один `TestViewModel` и существующий `TestExecutor`.
`StationDashboardViewModel` проецирует уведомления выполнения в этапы и результат,
управляет ожиданием ответа оператора; `StationStageViewModel` хранит состояние,
номер и раскрываемый список внутренних операций этапа. Список программ пульта
использует общий каталог профилей с отдельным поиском и короткими именами;
фильтрация не перезагружает выбранный граф. `StationProfileGroupViewModel`
хранит модель и состояние раскрытия; `StationProfileOptionViewModel` —
конфигурацию, команду выбора и выделение. Группы строятся по метаданным
`GraphProfile.DeviceModel` / `ConfigurationName`; коллекции обновляются
точечно. Метаданные корня сохраняет `GraphSerializer` через
`GraphWorkspaceViewModel`. Общей шапки нет: настройки доступны
внизу боковой панели пульта или под инженерными вкладками.
Оркестрация подключения/запуска/cleanup пока остаётся в `TestViewModel`,
отдельный второй исполнитель или новый формат графа не добавлялись.

`TestViewModel.Station.cs` задаёт доступность команд. Мутации графа проверяют
`CanEditGraph` и при прямом вызове; холст выключен во время теста. Скрытый
редактор не обрабатывает Delete. Профиль блокируется до конца cleanup.

`GraphCompiler` владеет созданными по умолчанию HTTP-клиентами и освобождается
после выполнения. Внедрённый тестовый `IHttpRequestService` остаётся во владении
вызывающего кода. Для выдачи серийника используется отдельный клиент с сессией
лаунчера, для DUT — прежний HTTP-клиент без этой сессии.

Проект построен как Avalonia desktop-приложение с MVVM, графовым редактором Nodify и отдельным доменным runtime для выполнения тестовых шагов.

## Проекты решения

| Проект | Назначение |
|---|---|
| `TestBuilder` | Основное desktop-приложение. |
| `TestBuilder.Tests` | Unit-тесты runtime-логики, сериализации и мониторинга. |

`TestBuilder.slnx` больше не содержит демонстрационные проекты Nodify. Это важно для Visual Studio/Rider: при открытии решения должны отображаться только основной проект и тесты.

## Разделение Node и Step

В проекте есть два уровня одной и той же логики:

| Уровень | Пример | Ответственность |
|---|---|---|
| ViewModel | `ModbusWriteNodeViewModel` | UI-параметры, коннекторы, клонирование, сериализация. |
| Runtime step | `ModbusWriteStep` | Реальная запись Modbus, проверка, возврат `StepResult`. |

`GraphCompiler` связывает эти уровни.

Пример:

```text
ModbusWriteNodeViewModel
  Title = "Запись регистра"
  Input: Вход
  Output: True, False
  Parameters: SlaveId, Address, Value, UseCurrentSlaveId, VerifyWrite
      |
      v
GraphCompiler.CreateStep()
      |
      v
ModbusWriteStep.ExecuteAsync()
      |
      v
StepResult.True / StepResult.False
```

## Поток данных при запуске теста

```mermaid
sequenceDiagram
    participant User
    participant TestVM
    participant Compiler
    participant Executor
    participant Step
    participant Context
    participant Observer

    User->>TestVM: RunGraphCommand
    TestVM->>TestVM: ResetToRootGraph()
    TestVM->>Compiler: Compile(RootGraph)
    Compiler-->>TestVM: CompiledGraph
    TestVM->>Context: new TestContext(RegisterState)
    TestVM->>Executor: ExecuteAsync(StartNode, Context)
    loop по узлам
        Executor->>Observer: NodeStartedAsync
        Executor->>Step: ExecuteAsync(Context)
        Step-->>Executor: StepResult
        Executor->>Observer: NodeFailedAsync при False
        Executor->>Observer: NodeFinishedAsync
        Executor->>Executor: выбрать Next/OnTrue/OnFalse
    end
```

## Состояние выполнения

`TestViewModel` реализует `IExecutionObserver`:

- `NodeStartedAsync` включает `IsExecuting`;
- `NodeFinishedAsync` выключает `IsExecuting`;
- `NodeFailedAsync` ставит `HasExecutionError`;
- для `SubtestNodeViewModel` дополнительно ведется прогресс вложенного графа.

`NodeViewModel` на основе этих флагов меняет рамку:

- обычная рамка - фиолетовая;
- выполняется - желтая;
- ошибка - красная.
