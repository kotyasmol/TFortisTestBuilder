# Перенос TFortisBoard в TestBuilder

Реализован в рабочем дереве 2026-10-14. Основа: TB `2395250`, RTL_v2 `86f7dbd`.
Полная матрица соответствия исходным этапам, адресам, паузам и отличиям:
[RTL_boards_migration](../RTL_boards_migration.md).
Проверки: [RTL_validation](../RTL_validation.md).

## Что согласовано и сделано

- JSON-файлы вместо БД. Описания оборудования входят в профиль, значения опроса
  остаются в памяти. Адресная доставка на заводы — отдельный файл конфигурации.
- «Оборудование»: шаблоны 10 моделей АПК-03, RTL-SW/PoE, пустое устройство,
  slave, RTU, необязательная идентификация, таблица Holding/Input/Coil/Discrete.
  Экспорт/импорт таблицы, сохранение вместе с графом. Без C# для стандартных регистров.
- «Платы / Коммутаторы»: фильтр профилей в том же приложении, без второго исполнителя.
- «Плата»: изображение, редактируемые области, ID в нодах, результат каждого
  связанного этапа, масштабирование и выбор элемента для ремонта. В пульте рисунок
  виден автоматически рядом с компактными этапами; увеличенный просмотр получает
  те же изменения результатов без сброса масштаба.
- For: режим повторения на одном slave, число попыток, индекс и пауза,
  остановка при успехе. Старый обход устройств сохранён.
- Serial Console, Run Program, Parse Response, Check LED Color; шаблон LED.
  Операторский ввод UID и сравнение минимальной версии.
- Графы RTL_SW_board и RTL_POE_board с вложенными именованными подтестами,
  исходными аппаратными адресами и завершающим снятием питания.
- Отчёты через штатные ноды TB, отдельный прежний EPL-макет платы, одна копия.
- «Настройки → Полная инструкция»: встроенное руководство с оглавлением/поиском,
  копированием и экспортом HTML. Описаны оба режима и все доступные ноды.

## Границы

Не добавлены БД, нода группового чтения, XGPro, клавиатурный эмулятор и FTServiceUtils.
Физический RUN исключён по решению владельца от 2026-10-19.
Сейчас запуск/отмена выполняются из TB. Прошивка платы — вручную вне приложения.

2026-10-19 получены RTL_SW_v1.json и RTL_POE_v1.json. Параметры перенесены
в готовые графы; оригиналы сохранены в tools/RtlProfileMigration/SourceProfiles.
Исправлены задержки K5/VCC: raw 10 вместо 2000, все пределы, версии, флаги,
цвет PoE blue и отключение питания порта 4. Отчёт/печать выключены, как в файлах.
Широкие допуски оригиналов сохранены без самостоятельного ужесточения.
Мониторинг 1000 мс; K5 ожидает 1, затем 2/3 через кэш без спама отказами.
Подробные отличия от исходного приложения — docs/RTL_boards_migration.md.
Оригинальные адреса и формулы LED перенесены, калибровочные коэффициенты не записываются.
Контуры PoE преобразованы в прямоугольные области поверх исходной схемы.

Сервер не дорабатывался. Контракт отчёта сохраняется; успешная работа сервера с
типами RTL-SW/RTL-POE и физическая печать пока не подтверждены. При раннем отказе
SW без серийника сохраняется журнал, серверный отчёт не фабрикуется.

Автотесты выполняют графы с подставными ответами, проверяют отрицательные сценарии,
сериализацию, UI и отмену. Это не заменяет приёмку на исправных/дефектных платах.

## Подтверждение виртуальными испытаниями 2026-10-15

Оба полных графа прошли через штатный фоновый опрос с исходными паузами:
SW 109,79 с, PoE 81,06 с. Это время имитатора, не производственный норматив.
Из 36 сценариев все дали ожидаемый результат; остальные 599 тестов также прошли.
Отправка отчёта и формирование этикетки больше не исключены из полного прогона:
перехватываются только HTTP и RAW-печать. PoE без печати — штатная настройка;
включённая печать и её отказ проверены отдельно. SW-заглушки версий проверены
отдельным ожидаемым отказом; для успешных прогонов заданы SIM-версии в памяти.
Производственные JSON не изменены.

Найден и исправлен случай, когда неудачное снятие питания, включённое в основную
цепочку, не приводило к заголовку «Проверьте состояние стенда». Полный обрыв
Modbus моделируется с неуспешными командами отключения: модель остаётся под
питанием, пульт не показывает успех, делает все попытки и требует проверки стенда.
Приёмка электроники, реальный сервер, этикетка и COM-драйвер остаются за инженером.
См. `docs/RTL_validation.md`, набор `TestBuilder.Tests/Simulation` и HTML в
`artifacts/rtl-simulation`.

### Уточнение DUT и прошивки, 2026-10-19

Подтест называется «Запуск и готовность DUT». Прошивка FLASH/MCU отсутствует;
необязательный запуск утилиты чтения UID выключен. Подсказка перед тестом
просит только установить плату и проверить подключения.
DUT подключается отдельным USB-UART через «Оборудование → Консоли»; это не
Modbus slave. Готовность определяется ответом SW_VERS (30 попыток, 3 с ответ,
2 с пауза). Пассивное ожидание загрузочных строк и автопоиск CH340 из RTL_v2
не перенесены. Команды и ожидания редактируются в графе. Подключение `dut`
в `hardware.ConsoleDevices` хранит порт, скорость, чётность, биты, кодировку,
окончание команды и DTR/RTS. Все консольные ноды SW ссылаются на `deviceId=dut`.
Порт выбирается перед первой проверкой и сохраняется в JSON. Старые профили
сохраняют резервные настройки рабочего места. Полный аудит границ —
docs/RTL_boards_migration.md.
