# Выпуск и диагностика — 2 ноября 2026

загрузка на корпоративный сервер, запуск через beta-лаунчер, диагностика

## Подготовка комплекта

В новые ZIP включены готовое Windows x64 приложение, встроенный .NET, portable
Chrome, WinSCP, лицензии, документы и четыре профиля:

- `PSW_UPS_Box_8x2Pro_parallel_start.json`;
- `PSW_2G6F_plus_full_algorithm.json`;
- `RTL_SW_board.json`;
- `RTL_POE_board.json`.

Это готовые файлы приложения, а не исходный C#-проект. Копирования одного EXE
недостаточно. `Start-TestBuilder.cmd` сохраняет переданные аргументы через `%*`.
Драйверы Npcap/COM, принтер, сетевые настройки, Stand ID и внешняя прошивка
PSW-2G6F+ не подменяются сборкой.

В репозиторном `parallel_start` включена существующая SFP-пара `.8/.9`
на 1000 Мбит/с в обоих направлениях. Четыре медные пары сохранены.
Три таймаута selftest в этапах 06, 07, 15 изменены 300000 → 250000 мс.
Ручные координаты не перестраивались. Для выбранных четырёх профилей
ProfileLayout обнаружил прежние замечания к отступам: 121 / 85 / 149 / 95.

Упаковщик получил повторяемый `--profile`: README и манифест отражают выбранный
комплект, остальные исходные JSON в репозитории не удаляются. Проверены CRC ZIP,
контрольные суммы и побайтное соответствие поставляемых профилей.

## Выполненная загрузка на сервер

1. Проверен распакованный комплект `.2` на рабочем столе Вышенской: все 720
   файлов совпали с манифестом, четыре профиля на месте. Из-за двойной вложенности
   источником была внутренняя папка, содержащая `TestBuilder.exe`.
2. Попытка создать соседнюю staging-папку в `Launcher_Beta` получила отказ
   доступа. Проверка доменного доступа подтвердила запись внутри существующей
   `TFortis_Stand_Builder`, но не создание папок рядом с ней.
3. Прежняя серверная папка полностью скопирована на рабочий стол Вышенской
   в `TFortis_Server_Backup_before_2026.11.02.2`: **722 файла**, каждый проверен
   сравнением хеша источника и копии.
4. В существующую серверную папку записаны файлы `.2`. Каждый из **720 файлов
   манифеста** проверен SHA-256 после записи.
5. После резервного копирования из активного набора удалены два старых варианта
   Pro: `PSW_UPS_Box_8x2Pro_full_algorithm_polling.json` и
   `PSW_UPS_Box_8x2Pro_parallel_el60.json`. Исходники в Git и резервная копия
   сохранились. Перед удалением прежние файлы сверялись с резервной копией.
6. Обновлён `release-manifest.json`. Существующий `version.txt` сохранён со
   значением **`2`**. Ассистент не менял этот маркер при загрузке.
7. Затем оператор сообщила, что вручную назначила **`3`** и запустила программу
   через beta-лаунчер на АПК03. Механизм автоматического обновления всех рабочих
   мест отдельным контролируемым испытанием не подтверждён.

Обновление сделано внутри существующей папки, а не атомарной заменой каталога.
При повторной публикации нужно исключить запуск программы на время копирования,
сначала сохранить резервную копию, затем проверять весь манифест и точный состав
`profiles`. Нельзя объединять новые и старые профили без сверки: удалённые
варианты останутся видны в приложении.

Для отката предназначена названная резервная копия, включая старые профили и
`version.txt`. Откат сегодня не выполнялся. Возврат файлов на сервер и получение
их клиентским лаунчером — отдельные действия; результат на рабочем месте нужно
проверять по версии и файлам, а не только по числу в `version.txt`.

## Аргументы лаунчера, COM и журнал

Оператор обнаружила три проблемы: автоматический COM останавливался на первом
открываемом порте, журнал обновлялся только после кликов, подготовка при открытии
не выполнялась ни на одном профиле даже при ручном COM3.

На АПК03 COM3 успешно обнаружил все 11 устройств. Подготовку блокировала ошибка
формата аргументов. Read-only разбор IL установленного `Stand_Launcher.StartStand`
подтвердил фактический контракт:

```text
TestBuilder.exe SESSION_ID "Имя оператора" HelpTypeInLauncher
```

Третье поле — целое число для справки. Это не пароль и не роль. Сессия и имя
должны поступать из лаунчера; вручную вводить пароль сотрудника в TestBuilder
не требуется. Поддержаны также прежние два аргумента, составное имя и
именованные `--session` / `--user`. Ошибка теперь видна в журнале и редакторе.

При автоматическом COM поиск продолжается после несовпадения оборудования
с выбранным профилем; ручной выбор остаётся фиксированным. `LogPanelView`
восстанавливает живой источник записей при открытии/присоединении; прокрутка
планируется с приоритетом Loaded, ручная пауза просмотра сохраняется.

70 целевых тестов прошли. Собран `.3`, позже изменения зафиксированы в `05583a6`
и перенесены в dev на АПК03. В последующем dev-журнале подготовка завершилась.
Устранение задержки живого журнала на производственном Windows отдельной
проверкой без кликов пока не подтверждено. Подробнее — [[09 - HTTP сеть отчеты печать]]
и [[10 - Настройки логирование тесты]].

## Нестабильная тестовая страница 8x2Pro

Первоначально выполнялось только чтение журналов. В успешных запросах в
12:35:33 и 12:36:17 разобраны 82 поля. Последующие запросы при проверке АКБ
возвращали пустой HTML; в следующем запуске встречался `ERR_CONNECTION_TIMED_OUT`.
Отсутствие свежего напряжения тогда не доказывало неисправность АКБ.

Причина воспроизведена на АПК03: у начального документа `about:blank` уже есть
`document.readyState == complete`. Старый код принимал его за нужную страницу,
ждал 10 секунд, снимал 39 символов `<html><head></head><body></body></html>` и
закрывал браузер до получения ответа. `complete` описывает состояние текущего
документа; оно само по себе не подтверждает адрес и содержимое тестовой страницы.

Исправление в `d03b1dc`:

- Chrome стартует с пустой вкладкой, затем `Page.navigate` явно открывает URL ноды;
- адрес, readyState и содержимое считываются согласованно; ожидается нужный документ;
- 10 секунд выдержки отсчитываются после его загрузки; навигация сбрасывает выдержку;
- перед попыткой требуется TCP-порт страницы, одного ICMP недостаточно;
- HTTP >=400 и ошибки навигации не считаются успешной страницей;
- сохранены ограничения времени, очередь браузеров и завершение собственного Chrome.

`SelftestProbe` с локальным HTTP-сервером, задерживающим ответ на 15 секунд:
старый код дал **5/5 провалов**, исправленный — **10/10 успешных чтений**.
Добавлены проверки задержки первого байта, тела по частям, HTTP 503, отмены,
таймаута и завершения Chrome. Также исправлена диагностика пути EXE при ошибке
запуска Windows. Все изменения отправлены в GitHub и собраны в dev на АПК03.

Оператор позже сообщила о пяти запусках без прежней ошибки. Это наблюдение
оператора, а не подтверждённый автоматический полный прогон всех этапов 8x2Pro.
Подробности — [[18 - Selftest и загрузка DUT]].

Во время программной диагностики `192.168.0.1:80` был недоступен. После отдельного
вопроса оператор явно разрешила управление AC1/AC2 штатными командами профиля,

подготовка, питание, selftest, нагреватели, медный DataTest, UPS и повторные

## Ошибка DataTest и защита параметров

В журнале `test-run_20261102_161804_PSW_UPS_Box_8x2Pro_parallel_start.txt`
в 16:21:20 DataTest остановился **до отправки пакетов**: вместо `SoftwarePcap`
в параметре `mode` находилось «Программный генератор трафика». Отключённая
проверка гигабитных/SFP-портов не была причиной этой ошибки режима.

Общий словарь русских подписей появился в коммите `3abac74` от 19 октября.
У read-only TextBox оставалась двусторонняя привязка: само отображение ноды
записывало русскую подпись обратно в служебный параметр. `IsReadOnly=true`
не запрещает такую обратную запись. Причина воспроизведена настоящим headless UI.

`acc825b` добавил OneWay для режима и совместимость: известная испорченная
подпись, старые aliases и пустое значение нормализуются в `SoftwarePcap`
при чтении/сохранении JSON и создании runtime-шагa. Неизвестные режимы остаются
ошибкой. Отключённые пары и скорости не меняются.

В пользовательском dev-профиле АПК03 заменён только испорченный `mode`.
До правки сделаны копии в диагностической папке:
`profile-before-mode-fix-163223.json` и `profile-mode-original-163609.json`.
Посимвольно проверено соответствие ожидаемой замене. `IsEnabled=false` у SFP
сохранён. ProfileLayout до/после: 21 граф, 165 нод, те же 120 прежних замечаний
к отступам, 0 перемещённых нод.

`ed50086` усилил защиту всего механизма:

- `RussianUiTextConverter.ConvertBack` всегда возвращает DoNothing, исключений нет;
- `ServerTestTypeConverter` переводит только production/repair; прочие серверные
  коды сохраняются дословно, даже при совпадении с SoftwarePcap/Json/green;
- `TranslatedNameColumn` переводит название для показа, а редактирует исходную строку;
- `ProfileUiIntegrityTests` отображает все 30 типов нод, 6 профилей, вложенные графы
  и редакторы кнопок, сравнивает исходные поля и JSON после сохранения/загрузки;
- штатный упаковщик обязательно пересобирает и запускает этот набор вместе с
  RussianInterfaceTests/DataTestModeTests до publish; при отказе ZIP не создаётся;
- результат проверки записывается в манифест, правила добавлены в AGENTS.md.

Проверка исходных полей до сериализации нужна, чтобы нормализация старого режима
не скрывала новую порчу значения интерфейсом. Это защита от данного класса
ошибок, а не доказательство отсутствия любых возможных дефектов.

Dev Debug обновлён на АПК03 после остановки отладки; последняя сборка в этой
сессии — 17:02:42, 0 ошибок. При последнем git pull профиль сохранился побайтно
(SHA256 до/после совпал). Эти исправления не были повторно залиты в серверную beta.
Подробнее — [[06 - JSON профили]] и [[10 - Настройки логирование тесты]].
