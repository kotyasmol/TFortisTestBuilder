# Быстрый старт

## Требования и сборка

Основное приложение — Avalonia 11.1 / .NET 8. Для разработки нужен .NET SDK;
COM-драйверы, Npcap и RAW-печать проверяются отдельно на производственном Windows ПК.
Базовый запуск UI поддерживает также macOS/Linux. Windows-программы, bat-файлы,
настройка адаптеров и очередь принтера не становятся переносимыми вместе с UI.

Из корня репозитория, в том числе с SDK 8 без поддержки `.slnx`:

```powershell
dotnet restore TestBuilder.Tests/TestBuilder.Tests.csproj
dotnet build TestBuilder.Tests/TestBuilder.Tests.csproj
dotnet run --project TestBuilder/TestBuilder.csproj
```

`TestBuilder.slnx` включает TestBuilder и TestBuilder.Tests. Тестовый проект
дополнительно ссылается на `tools/ProfileLayout`. Локальная копия Nodify не входит
в решение: приложение использует NuGet NodifyAvalonia 6.6.0.
Известные предупреждения сборки: NU1701 для NModbus4, nullable и AVLN3001 для
диалогов; успешная сборка не подтверждает работу оборудования.

## Первое знакомство

Первый запуск предлагает «Пройти обучение». Это отдельное окно с временными
профилями без аппаратных команд. Повтор: «Настройки → Интерактивное обучение».
Руководство: «Настройки → Полная инструкция»; 54 статьи, включая все 30 нод палитры.

По умолчанию открывается пульт. В верхней панели «Открыть редактор» переводит
в инженерный режим; «Перейти в пульт» возвращает обратно. Режим можно менять
во время теста, редактирование графа остаётся заблокированным. Настройки доступны
в верхней панели обоих режимов; «Вернуться к работе» закрывает их.

Инженерные страницы: «Редактор», «Регистры», «Этикетки», «Самопроверка», «Сеть».
Для автономного стенда платы инструменты коммутаторов могут скрываться.
«Оборудование» открывает каталог и состав устройств профиля; для платы доступен
редактор изображения и областей. Подробнее — [[03 - Работа с приложением]].

## Профили

В `profiles/` находятся шесть производственных профилей: RTL-SW, RTL-PoE,
PSW-2G6F+ и три варианта 8x2Pro. Демо и ручные примеры находятся отдельно
в `examples/profiles/`; для показа в приложении их нужно импортировать.
Вариант `PSW_UPS_Box_8x2Pro_parallel_start.json` сейчас предназначен для восьми
медных портов без SFP и не является полной проверкой всех портов устройства.

Папку показывает «Настройки → Профили тестирования → Папка с JSON-профилями».
Кнопка «Выбрать папку» меняет источник списка, но не переносит файлы.
При отсутствии пригодного сохранённого пути `ProfileDirectoryLocator` ищет
репозиторную папку `profiles`, затем папку рядом с EXE. Производственные JSON
и каталог включаются в build/publish, `examples` автоматически не включаются.

В списке профилей ПКМ → «Копировать профиль…» создаёт отдельный JSON;
«Переименовать…» меняет название проверки в прежнем файле. Модель и название
отображаются одинаково в списке и редакторе. «Сохранить» обновляет текущий файл;
изменение названия открытого графа с последующим сохранением также создаёт копию.
«Импорт» не перезаписывает существующий одноимённый файл.

## Подключение и запуск

1. Включить стенд. При нескольких COM-портах при необходимости указать нужный
   в «Настройки → COM стенда». Пустое поле включает автоматический выбор.
2. Нажать «Подключиться» в редакторе или «Подключить» в пульте. Программа
   открывает порт с параметрами «Параметры открытия COM-порта…». Успех здесь
   означает только открытый порт; Modbus-чтений при выборе порта нет.
3. Выбрать профиль. На этом же порту проверяются все устройства из `hardware`,
   запускается мониторинг и выполняются ноды «При открытии профиля».
4. Дождаться успешной подготовки и вручную нажать «Запустить» / «Начать».
5. После завершения заменить изделие и повторить запуск. Настройка стенда
   повторяется при реальном повторном открытии профиля или новом подключении.

Если профиль выбран до подключения, его проверка и подготовка выполняются
после открытия порта. Смена профиля не перебирает другие порты. При ошибке
оборудования или подготовки основной тест заблокирован; причина — в журнале.
Повторная проверка: открыть профиль заново. Кнопка запуска не повторяет подготовку.

Явный COM используется без перехода на другой порт при ошибке. Автоматический
режим перебирает имена лексикографически (`COM1`, `COM10`, `COM2`) и выбирает
первый успешно открытый порт; свободный порт может оказаться не портом стенда.
Профиль содержит ожидаемые slave и регистры, а не номер COM. Подробнее —
[[07 - Modbus и мониторинг]].

## Работа без оборудования

Можно создавать, копировать и редактировать профили, смотреть справочник
регистров, собирать вложенные графы и кнопки профиля. Сценарий без Modbus и без
заданного состава RTU-оборудования можно выполнять без подключения.
Минимальный пример: «Старт → Задержка → Конец».

Для ручной печати открыть «Этикетки»: выбрать шаблон, ввести серийный номер
и MAC, указать количество и нажать печать. Для получения данных с сервера есть
поиск по MAC или серийному номеру; сетевой доступ и ответ сервера обязательны.
Кнопка повтора использует последнюю успешно отправленную этим окном этикетку.
Принтер и нужный ему язык команд задаются в шаблоне; RAW-печать работает в Windows.

## Лаунчер

```powershell
TestBuilder.exe SESSION_ID "Имя оператора"
TestBuilder.exe --session SESSION_ID --user "Имя оператора"
```

Сессия хранится в памяти, требуется серверным операциям, которые используют
авторизацию лаунчера. Имя не даёт инженерных прав. Режим интерфейса — локальная
настройка, не серверная роль. Неизвестные/неполные параметры блокируют запуск
теста. «Сессия лаунчера получена» означает получение аргумента, а не проверку сервером.

## Проверки

```powershell
dotnet test TestBuilder.Tests/TestBuilder.Tests.csproj --no-build
```

Тесты включают runtime, JSON, профили, аппаратные и сетевые двойники и Headless
Avalonia. Для проверки конкретной правки используют `--filter`; полный запуск
не заменяет производственный прогон. Последние результаты — [[13 - Карта актуальности]]
и [[17 - Журнал проверок]].

## Готовый комплект Windows 2026.10.19.16

Это зафиксированный выпуск от 2026-10-19, не текущий master.
Для Windows 10/11 x64 был подготовлен автономный ZIP
`TFortisTestBuilder-2026.10.19.16-win-x64`: распаковать целиком в доступную для записи
папку и запустить `Start-TestBuilder.cmd`. Включены .NET, native-библиотеки,
Chrome for Testing для selftest, WinSCP, bat-файлы, все 6 профилей и документация.
Устанавливать SDK/.NET/браузер на целевой ПК не требуется.
Профили: RTL-SW, RTL-PoE, PSW-2G6F+ и три варианта 8x2Pro.
Картинки, области, привязки нод и параметры оборудования плат находятся внутри
JSON. Поиск стенда и ожидание DUT настроены; прошивка плат выключена.
Получение серийных номеров остаётся серверным этапом и требует сессии лаунчера.
Начальные настройки: пульт, светлая тема, файловые логи, Stand ID «тест»;
папка profiles определяется рядом с EXE. Комплект лежит в
`artifacts/windows-20261019`, версия и SHA-256 указаны в манифесте.

`Check-Installation.cmd` проверяет комплект и наличие внешних компонентов,
сохраняет `installation-check.txt`. Npcap, драйвер COM-адаптера и очередь
принтера остаются требованиями Windows; их установщики в релиз не включены.
Прошивка PSW-2G6F+ отсутствует в репозитории и по согласованию остаётся по
исходному пути `C:/FortTelecom/Launcher/TFortisStandNew/firmwares/sw407/`.
Перед реальным тестом нужны привязка сетевых карт, фактический Stand ID и
действующая сессия корпоративного лаунчера для серверных операций.
Привязки сетевых карт и Npcap относятся к DataTest коммутаторов, для проверок
плат SW/PoE они не нужны. Stand ID необходимо заполнить перед отправкой отчёта.

Файловые логи включены в настройках релиза. Сборка и список внешних требований:
`packaging/windows/BUILD.md`, операторская инструкция: `README-FIRST.txt`
в корне ZIP. Следующие разделы про SDK относятся к запуску из исходников.
