# Быстрый старт

## Требования

- .NET 8 SDK.
- Windows, Linux или macOS для Avalonia UI.
- Для реального стенда: COM-порт с Modbus RTU устройствами.
- Для DataTest: Npcap/WinPcap и права доступа к сетевым адаптерам.
- Для печати этикеток: Windows и установленный RAW/Zebra-совместимый принтер.

## Сборка

Из корня репозитория:

```powershell
dotnet restore
dotnet build TestBuilder/TestBuilder.csproj
```

Решение описано в `TestBuilder.slnx`. В него входят только основной проект и тестовый проект:

- `TestBuilder/TestBuilder.csproj`
- `TestBuilder.Tests/TestBuilder.Tests.csproj`

Локальные исходники Nodify лежат рядом в `nodify-avalonia-avalonia_port`, но демонстрационные проекты Nodify не подключены к решению TestBuilder.

## Запуск приложения

```powershell
dotnet run --project TestBuilder/TestBuilder.csproj
```

После запуска откроется `MainWindow` с вкладками:

- `Тест` - сборка и запуск графов.
- `Modbus` - просмотр найденных slave и регистров; вкладка активируется после обнаружения устройств.
- `Настройки` - папка профилей и тема.

## Первый запуск без оборудования

Без стенда можно:

- открыть приложение;
- создать граф;
- добавить ноды из палитры;
- сохранить профиль в JSON;
- загрузить существующие профили;
- изучить логи UI;
- запускать unit-тесты.

Без Modbus-подключения нельзя полноценно выполнить граф, потому что `RunGraphAsync` проверяет `IsConnected` и не стартует тест, если стенд не подключен.

## Настройка папки профилей

1. Открыть вкладку `Настройки`.
2. В поле `Папка с профилями тестирования (JSON)` нажать `Обзор...`.
3. Выбрать папку.
4. Профили `*.json` из этой папки появятся на вкладке `Тест`.

Настройки сохраняются рядом с exe в файл `testbuilder.settings`. Класс: `AppSettings`.

## Подключение к стенду

На вкладке `Тест` нажать `Подключиться`.

Что делает приложение:

1. Получает список COM-портов через `SerialPort.GetPortNames()`.
2. Последовательно пробует открыть каждый порт с параметрами `9600, Parity.None, 8, StopBits.One`.
3. Проверяет порт пробным чтением `ReadRegistersAsync(1, 0, 1)`.
4. Сканирует slave ID от `1` до `35` с шагом `2`.
5. По значению регистра `0` выбирает модель устройства.
6. Запускает `RegisterMonitor`.
7. Заполняет `SlaveRegistry`, чтобы Modbus-ноды могли показывать список устройств и регистров.

## Создание простого графа

Минимальный граф:

```text
Старт -> Задержка -> Конец
```

Чтобы выполнить полезную Modbus-операцию:

```text
Старт
  -> Запись регистра
  -> Проверка равенства
  -> Конец
```

Для условного перехода:

```text
Проверка равенства.True  -> успешная ветка
Проверка равенства.False -> обработка ошибки
```

Важно: если `False` никуда не подключен и шаг вернул `False`, `TestExecutor` завершит граф со статусом `Failed`.

## Сохранение и загрузка

- `Сохранить` открывает системный SaveFilePicker и пишет JSON через `GraphSerializer.Serialize`.
- Выбор профиля в списке загружает JSON через `GraphSerializer.Deserialize`.
- `Импорт` копирует выбранные JSON-файлы в папку профилей, если файлов с такими именами еще нет.

Подробнее: [[06 - JSON профили]].

## Запуск тестов

```powershell
dotnet test
```

Тесты покрывают:

- проверки переменных;
- проверки регистров;
- задержку;
- запись Modbus с read-back verification;
- HTTP/production steps;
- selftest parsing;
- subtest execution;
- сериализацию `Subtest`;
- `RegisterState`.
