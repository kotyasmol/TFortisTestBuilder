# Справочник TFortisTestBuilder

Папка `reference` поставляется вместе с программой. Её можно копировать
целиком или переносить отдельные разделы.

| Путь | Содержимое |
| --- | --- |
| `boards/RTL/` | PNG и JSON с областями плат RTL-SW и RTL-POE. В редакторе платы выберите «Шаблон платы…» и откройте JSON рядом с его PNG. |
| `modbus/hardware-presets.json` | Общие устройства Modbus, их идентификация и карты регистров. В редакторе оборудования доступны в списке готовых устройств. |
| `serials/equipment-models.json` | Названия и ID изделий, коды этикеток, серверные типы и подтверждённые диапазоны. |

Изображение и области, применённые к профилю, сохраняются в его JSON.
Личные шаблоны оборудования остаются в `equipment-library.json` в
локальных данных приложения. Личный или общий каталог моделей можно
держать в `catalog/equipment-models.json` внутри настроенной папки профилей.
Записи этого каталога имеют приоритет по ID.

Для RTL-SW и RTL-POE используются коды этикеток 313 и 312 соответственно.
В `rtlReport` указан числовой тип JSON-отчёта из протокола RTL_v2. RTL-SW
запрашивает номер через `getSerialNum` по DEVICE_ID. Для RTL-POE
`assignSerialOnReport` включает выдачу номера в ответе на отчёт по MCU ID.
Диапазоны обеих плат задаёт сервер.

Поле `rtlReport.failureDeviceIdentifier` задаёт серверную запись для отказов
до получения номера платы. В комплекте используются идентификаторы из RTL_v2.
Числовой номер этой записи возвращает сервер. Его можно увидеть в журнале
и локальной копии отчёта. Переопределение для рабочего места можно добавить
в каталог профилей по тому же ID модели.

## Редактирование и передача

Откройте **Справочник → Все изделия…**. Найти карточку можно по названию,
альтернативному названию или коду этикетки (`026`). Внизу окна показаны
полные пути файла поставки и локальных изменений. Карточка сохраняется
в `catalog/equipment-models.json` активной папки профилей; файл поставки
редактор не меняет. Переносите этот каталог вместе с профилями. На другом
рабочем месте объединяйте записи по ID, сохраняя его локальные карточки.
Для включения проверенных изменений в выпуск внесите их в
`reference/serials/equipment-models.json` исходников. Сборка копирует `reference`
рядом с приложением. Списка моделей в коде C# нет.

В поставке предзаполнены серии 31 коммутатора. Для старых моделей 001–031
имена сверены с `DevicesDescriptions.cs` исходников сервера на Вышенской;
база и MAC соответствуют `psw_stand-dev/test.cpp` (тип × 100000 и четвёртый
байт MAC). Существующая серия PSW-2G6F+ сохранена без изменения. Для PSW-2G8F+Box:
тип `PSW-2G8F+Box`, диапазон `2600001–2665535`, база `2600000`, MAC
`C0:11:A6:1A`, код этикетки `026`. Это настройки клиента; наличие типа и
фактическую выдачу на производственном сервере следует проверить отдельным
согласованным прогоном. Коды остальных изделий не преобразуются в серии
автоматически. Неизвестные серверные параметры остаются незаполненными.
Кнопка **Заполнить из поставки** на вкладке серийных номеров восстанавливает
предзаполненные поля выбранной модели, в том числе при локальном переопределении.

`labelVariants` — названия комплектаций с кодами 0–9. Отдельное поле
`labelCabinets` — короткая подпись шкафа для того же кода. Например:

```json
"labelVariants": { "1": "Plastim + PWR180" },
"labelCabinets": { "1": "Plastim" }
```

В карточке есть вкладка **Шкаф на этикетке**. Выбирайте комплектацию профиля
в меню **Справочник → Комплектация этикетки**. Код комплектации остаётся первой
цифрой штрихкода. Подпись шкафа печатается рядом с полным SN; пустое поле
отключает её. Штатный ZPL резервирует место только при наличии подписи.
Настройки ширины поля и высоты текста — **Настройки → Настроить печать этикеток…**.
Пользовательские команды сохраняются; для них доступны `{{Cabinet}}`,
`{{CabinetField}}` и `{{SerialTextWidth}}`. Последние два работают вместе со
строкой `^FOx,y^A0,25,{{SerialTextWidth}}^FDSN: {{Serial}}^FS`.
