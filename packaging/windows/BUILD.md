# Переносимая сборка Windows x64

Зафиксированный комплект от 2026-10-19 (не текущий master): `2026.10.19.16`. Включает четыре профиля
коммутаторов и по одному для SW/PoE. Изображения, области и оборудование
плат встроены в JSON. Базовые настройки создаются заново; настройки личного
компьютера и сессии не копируются.

Если официальный архив Chrome уже недоступен локально, можно использовать
браузер из ранее проверенной местной сборки:

```text
python3 scripts/package_windows_release.py --browser-bundle artifacts/TFortisTestBuilder-1.0.0-win-x64 --version 2026.10.19.16 --output artifacts/windows-20261019
```

Перед копированием проверяются версия браузера, полный состав его файлов
и SHA-256 по манифесту прежней сборки. `--version` передаётся также в publish;
без параметра используется версия проекта. `--browser-zip` и `--browser-bundle`
взаимоисключающие. Проверка комплекта требует встроенного изображения у плат.

На машине сборки нужны .NET SDK 8, Python 3.9+ и доступ к NuGet при первом
restore. На целевом Windows-компьютере Python, SDK и отдельный .NET не нужны.

1. Скачать официальный архив браузера по `url` из `browser.json`.
   Версия и SHA-256 закреплены; упаковщик отклоняет другой архив.
2. Выполнить проверки:
   `dotnet test TestBuilder.Tests/TestBuilder.Tests.csproj -c Release`.
3. Для выпуска из рабочей копии манифест сохраняет `sourceCommit` и
   `sourceDirty`; контрольные суммы описывают фактически собранные файлы.
4. Из корня репозитория запустить:

   ```text
   python3 scripts/package_windows_release.py --browser-zip /path/to/chrome-win64.zip
   ```

   На Windows команда Python обычно называется `python`.

Результат в `artifacts/`: каталог `TFortisTestBuilder-1.0.0-win-x64`, ZIP и
SHA-256 ZIP. Уже существующий релиз не перезаписывается: для повторной сборки
укажите `--output /path/to/new-directory`. Бинарники/архивы исключены из Git.

Упаковщик выполняет `dotnet publish -c Release -r win-x64 --self-contained true`
без trimming и single-file, добавляет Chrome, все актуальные профили и
отслеживаемые Git документы. Профили проверяются побайтно; пути прошивок не
переписываются. Настройки нового стенда создаются заново, файловый лог включён.
Проверяются обязательные native/managed-компоненты, AMD64 apphost, встроенный
.NET, контрольные суммы файлов и CRC ZIP. Скрипт не запускает Windows-приложение
на другой ОС и не заявляет проверку аппаратного стенда.

В `licenses` копируются nuspec и доступные license/notice-файлы зависимостей;
WinSCP сохраняет собственную лицензию, Chrome — файлы исходного архива.
Дополнительные тексты из официальных репозиториев библиотек/шрифта находятся
в `licenses/upstream`; их источники записаны в `sources.json` в той же папке.
Список пакетов — `licenses/nuget-packages.json`. Исходный архив Chrome остаётся
внешним входом сборки, его URL/версия/хеш записываются в манифест.

Граница комплекта согласована: отсутствующая прошивка PSW-2G6F+ остаётся по
исходному пути; Npcap OEM не предоставлен, свободная редакция не включается.
Драйверы USB–RS-485 и принтера зависят от оборудования. `README-FIRST.txt`
перечисляет эти требования; `Check-Installation.cmd` проверяет локальную
комплектность, драйвер Npcap, наличие COM и очереди принтера без изменения
настроек Windows. Коды выхода: 0 — без замечаний, 1 — ошибка проверки или
комплекта, 2 — замечания к настройке/изменённые оператором файлы.
